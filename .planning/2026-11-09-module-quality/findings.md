# 模块审查发现

2026-11-09 基线为 `master` 上的 `62602102a`，工作树有 570 条既有状态记录。上一轮的边界与兼容修复在当前工作树内。审查以实际运行入口和当前文件为准。

每条发现应记录实际调用点、触发条件、根因、影响范围以及验证。明确区分业务资源上限、真实性校验与可省掉的表示限制。

## 三项遗留的关闭方式

- 严格来源读取器先执行实际准入、稳定字节和范围验证。复用同一次观察的路径和收据，服务完成时无需再次读取。候选位置并发重绑时，回传本次实际打开的位置。只在同一次采集事务内部传递观察，公开的新调用须重新验真。提供商发现前后及锁内变化属于不同观察。
- PPTX 以独立字段保存原生正文覆盖和整页素材缺口。正向引用仍可验证，纯文本、混合页和空选据各按实际覆盖处理。确认不可见的图片跳过新 OCR，旧引用保留真实位置。按使用的解析器指纹更新当前缓存。
- SourceExport v1 清单保留真实文件名的 Unicode 拼写。旧 NFC 路径优先精确定位，其余仅在逐级唯一且根内时重放，仍实读校验 SHA。旧 `--base` 和现有清单冲突语义均可继续使用。

## 发布候选 CI 的根因

- 本地固定 smoke 与 CI 单元组覆盖范围不同。首个冻结提交通过静态检查、定向和组合用例后，CI 单元组仍发现测试依赖旧的导入、旧 DTO 和不完整的模拟返回。测试改用实际 owner、公开 DTO 及真实 fixture，保留正反例的业务断言。冻结 v3 生产者只在测试子进程补足迁移后的公共函数别名，按原始冻结字节验证历史已付费恢复。
- Phase C benchmark 还从旧来源模块导入请求准备函数。实际请求入口改用 AUTO owner，本机模型环回同时检查首跑请求、恢复时零新增请求和收据保留。
- 同发行人的真实财年和目录旧标签冲突时，非 pin 的采集入口能按原件更正范围并对原请求返回缺失。下一次请求正确财年会复用同一来源。严格 pin、错发行人、下载暂存的拒绝继续单独验证。
