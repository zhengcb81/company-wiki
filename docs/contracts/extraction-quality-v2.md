# Extraction Quality Diagnostic v2

This is **source/extraction quality only**, never an investment conclusion or a
manual authorization gate. The exact `source_id` or `document_id` selects one
source. Missing and ambiguous identities fail explicitly. The CLI returns schema
`2.0.0`; v1's assumption that every document needs whole-document normalization
no longer applies.

## States and coverage

- `metadata_only`: a source is indexed but has not been requested for extraction,
  or its legacy extraction has been retired. It is a normal state. No conversion,
  download, LLM call or permanent full-document spans are generated by this query.
- `skipped_no_narrative`: a visible, valid final bundle records a policy skip. It
  has zero parsed spans, not a fabricated successful extraction.
- `usable`: the chosen extraction has usable output without a technical quality
  issue. This can be selected narrative evidence; it does not claim every sentence
  or financial table was retained.
- `review_required`: output has partial coverage, extraction flags or a recorded
  technical issue. This is a diagnostic, not a demand for a human signature.
- `unavailable`: source locations are unavailable, the source is withdrawn or
  quarantined, or an attempted extraction is blocked/unsupported/failed.

`extraction.basis` is `selected_narrative`, `legacy_normalization` or
`metadata_only`. `selection_status` and `coverage_complete` describe only the new
selector's recorded scan coverage, not completeness of every business fact.
`raw_bytes_verified` is always false: quality queries do **not** reread raw bytes.
Consumers must use the existing source reader/narrative transport to verify the
current original SHA and replay citations when actually consuming content.

## Read order and consistency

1. Prefer the latest **visible** narrative bundle for the exact current source.
   Prepared versions remain invisible. Reuse the existing artifact reader and
   strict `NarrativeBundle` contract: enforce the final byte cap, object SHA/size,
   source identity/size/MIME, policy, selection and quality binding. Do not silently
   fall back to legacy data when a current final is corrupt.
2. When no visible final exists, a non-retired legacy normalized artifact can be
   assessed during migration. Its metadata and all legacy EvidenceSpan records
   retain the existing consistency checks. This is read compatibility, not a writer.
3. Without extraction, or with a retired normalized handle, return metadata_only
   without reading the old span table. Retired metadata is historical provenance.

An integrity conflict raises `ExtractionQualityIntegrityError`. The `normalization`
object remains as a compatibility field group; generator and counts now describe
the chosen extraction, with null generator/parser fields for metadata_only.

## Bounded, body-free output and no writes

Status counts, parser/version/quality flags and **locator references** contain no
`raw_text`, `structured_value`, summary bodies, paths or research fields. Locator
references are sorted and explicitly truncated. `locator_limit` is 1–500,
default 100. A narrative query processes only the already bounded final object.

The existing SQLite session uses `mode=ro` and `query_only=ON`; a static database
also uses `immutable=1`. An active WAL requires an existing SHM. Bundle reads
borrow this session, so they do not open a second connection or create sidecars.
No DML/DDL, catalog initialization, raw file reads or quality-state writes occur.

```powershell
python -m company_wiki.source_catalog.cli --config config/source_catalog.yaml extraction-quality --document-id <document-urn> --locator-limit 100
python -m company_wiki.source_catalog.cli --config config/source_catalog.yaml extraction-quality --source-id <source-urn>
```
