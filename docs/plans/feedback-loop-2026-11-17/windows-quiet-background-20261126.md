## 设计

1. 现场观察、隔离验证和正式部署各有入口。现场观察只访问已经存在的服务，离线即返回可读状态。隔离端口和写目录归测试，默认使用本地替身来验证跨模块协议。实机组合验收按已明确的任务范围使用现有服务，不由测试启动、接管或回退正式监听。正式部署走所属模块公开入口并绑定当前验收版本。
2. 每个模块在自己负责的后台子进程边界统一处理 Windows 启动。对于已指向具体安装目录的 Python，优先使用同安装的 `pythonw.exe`，并设置 Windows 无控制台创建参数。保留既有输入输出流、超时、进程树回收和错误证据。主动在终端运行的 CLI 沿用原语义。配置内的解释器仍表示既有安装；窗口方式在创建子进程时决定，不改作业身份或历史指纹。
3. 使用现有运行日志标识后台启动者、模块、入口、相关号、解释器种类和子进程号。记录 PID 与创建时间以区分复用，不写原始凭据和完整命令。CWP、Dashboard 和 FF 已有进程传输边界，分别核对直属和下一层；IQS 将五处 workbench 进程调用收敛到本仓边界。若独立工具内部的孙进程无法从调用接口约定为无窗，把该类无人值守工作放到非交互宿主验证，保留用户桌面用于显式前台操作。

## 施工与验收

| 阶段 | 动作和验收 |
| --- | --- |
| 现场止扰 | 保持 Dashboard、共享 F4 暂停。使用原日志和只读进程记录确认其他监听、隔离验收及下游调用。不开服务、不发真实请求、不改 Windows 审计策略 |
| IQS 边界 | 先用替身固定 Windows 下同安装 `pythonw.exe`、后台标志和输入输出透传。将实体、回跳、资料准备和作业启动迁入同一 transport，保留原配置和运行账本 |
| Dashboard 验收 | 沿已有隔离夹具收敛服务启动，现用端口离线的验证只能产生状态观测。独立用例应能在无正式监听和无真实 owner 时运行。并行作业不得隐式恢复 `48766` 或访问实际 IQS 进行默认回归 |
| 启用前复验 | 在受控宿主用跨挂牌场景覆盖 Dashboard 与 IQS 两层，不依赖现场用户桌面。同时对照窗口数、解释器、子进程、输出、退出号和数据指纹。两次单步运行无窗口后，再按用户恢复指令启用现场服务 |
