## 问题和写入范围

DeepSeek 的 HTTP 失败、429 重试和传输异常可能把第三方响应正文或异常字符串写入命令输出及 owner 诊断。沿本仓现有发布与观察接口修正该 DeepSeek 边界。只改 DeepSeek 客户端、必要的本仓原生诊断投影、定向测试和本仓 F4/S2 PWF。技能副本、CWP 配置、报告生成、quick scan 和其他仓留给各自负责人。已有安装器可作为发布前的只读合同参考。

## 实施与测试

1. 在临时根用真实 CLI 和本地 HTTP 替身复现 500 供应商正文、429 后成功、传输异常和正常成功。只给合成输入和凭据，在测试内禁止真实网络和付费。用断言验证既有退出、结构化产物、请求和重试次数。
2. 在供应商边界保留 HTTP 状态、尝试序号、异常类型和可用原因位置。把原始 HTTP 响应和任意第三方文本留在瞬时调用中。用本仓既有日志与 F4 观察引用记录安全诊断，保留成功 stdout 结构及未知用量的原状态。
3. 原进程退出后用本仓公开入口取回诊断，再通过原 F4 观察接口核对同一 run、attempt 和 step。复查 stdout、stderr、诊断、sidecar 和控制端输出，高敏测试值应只存在输入。冷读应零新请求，成功重试不应被诊断改成失败。
