## 已对齐的恢复设计

宿主先登记原观察，再处理同阶段的偏差。配对终态可来自同一文件或已确认的原观察。开始时尚无引用的旧入口仍可由同一阶段的终态补上第一份引用。过往终态损坏、原观察冲突或实际仍在运行时，保留原作业查账。拒绝仍进入门禁必要性分诊，费用未知继续走原用量查询。

用 376 个现场包的逐字节隔离副本和原宿主已确认的观察重放两轮。每轮剩 110 包、112 条，继续保留 79 个对账和 33 个待分诊发生。两轮都没有唤醒业务动作，未新增下载、模型或费用。源和复制的观察正文 SHA 一致。隔离重放只复用了原查账结果，正式调度验证单独记录。

## 剩余故障和处置

- RF 9 个 CLI 失败均从原账按发生号读回。3 条缺 `--owner-root` 的参数，原业务未启动；6 条作业标识不符合公开格式，原调用未留操作类型，原副作用未知。RF 16 个来源阶段终态保留原因码，正式 owner 根缺对应原作业。11 月 25 日三个短时间段中的一组来源错误和三组 CLI 现象与当前测试运行顺序、原因、源代码位置重复吻合。按测试证据处理已证测试隔离缺口，其余记录继续保留。
- FF 6 个短请求故障的原 traceback 与历史源码 SHA 均可读。都是状态查询在打开作业存储前收到不规范的作业标识，当次查询未派发。原实参、调用者和目标作业用量仍未确认。另两项真实周任务读回 `partial`，每项 2 个失败、1 个待续、0 次下载，原用量未知。完整逐项输入缺失。
- RF 与 FF 的修理入口应复用本仓原诊断及公开作业读面。无原输入时保留证据缺口，历史回告只有在绑定版本复验后才可写入。已有失败侧带、原预算和模型调用约束适用于继续处理。
- [正式部署验收](deployment-acceptance-20261126.md) 继续记录 Dashboard 和行业研究的私有 CI、RF 两个 SYSTEM 定时任务，以及共享调度实际采用结果。

## 验收顺序

1. 从公开宿主复现跨文件漏配和分诊原因丢失。
2. 覆盖同文件与跨文件、不同尝试、不同证据、旧 SID、冲突记录、终态失败与费用未知。关键结果由独立 agent 复验。
3. 复用原共享 Windows 开机和定时任务，观察已经配对的开始记录不再触发 owner 查账。对照作业动作和用量记录。
4. RF、FF 各自在本仓修复已复现的故障记录语义。完成剩余部署实证后，沿 [W12](../du11-source-closure-2026-10-18/CURRENT_STATUS.md) 接续业务摘要。
