# 设计依据

2026-11-21 的 IQS 事故和 12 仓冷读确认，原验收覆盖的是已进入反馈的场景。部分普通入口在创建观察前退出，部分丢失原因链，另有业务失败被协议检查或费用状态遮蔽。SID 的失败队列在写盘前清空，Audit 的诊断截断会改变原退出的解读，IR 和 RF 存在安装版与受测源码不同。今后按原生运行清单对账，保存原生终态、反馈投递与计量三组独立事实，并从实际安装、HTTP、worker 和定时器抽样。[原始证据和复现](failure-coverage-20261121.md)

- MC 运行端口独审验证了三个证据根因。原发生链及兄弟终态需核对归属与版本。同一步骤还在逐行追加时，不能将半批偏差固定成缺证终态。旧版事后读取输出路径可能把后续同时发生的写入算给旧作业。复现分别落在公共端口测试、通用总控半批测试、实际原子 writer 测试。
- MC 自动修复使用已保存 writer 事实重建发布清单并让消费方复验，原转录和费用沿原作业。MC 的回执与 ROOT 的调度记录各归本仓。在修复和回告持久保存后让接收进程硬退出，两次恢复查回原 action。

- MC 正式交接为 `b1acea5`，受审源码 `8806ff4`。ROOT 独审实读作者的重投侧车，11 行只得到 5 条有效观察，3 个冲突使已完成转录变成悬空开始。两次实际执行要各有自己的步骤身份，同一份已写出的观察可以原样重投。
- MC 独审另复现四类旁路问题：禁用后仍读产物且探测报错能改变业务结果，任意异常文本进入步骤详情，截断的旧侧车吞掉下一条开始记录，输出位置是目录时被误判为旧译文。修订限于 MC 反馈投影及必要接线。ROOT 继续使用通用协议。
- StockWiki、IQS、Dashboard、StockQA 四张接续卡已由用户转交现有 harness，重叠写入留在各自原线队列。

- FF 短请求接收初查为 `8d1228d` 正式交接，受审源码 `eb2ee5c` 之后仅交接文档改动。
- ROOT FF 独审实测 `filing_intent` 为数组或对象时保持原业务错误，但旁路漏记终态。原因是旁路把原请求字段用于集合查询。经真实 CLI 的两个 RED/GREEN 验证，类型检查让终态正常记录，业务结果和原生调用数相同。

- F4 既有测试只覆盖宿主侧收据写完后丢数据库更新。如果责任仓已经原子保存回告，但负责转送 stdout 的进程提前退出，宿主侧只有开始记录。FF、RF 已有公开 `get-report ACTION_ID`，能按原 ID 回读完整请求。ROOT 可以核对原发现、修复版本、复验引用和请求摘要后补回原状态。用实际责任仓命令验证，无需改 F2 的两个工作树。
- 本轮 F2 补位复核了工作树、在途改动和实际接口。MeetingConverter 的主工区仅见历史覆盖率写入，转录发布反馈可从干净的远端同版工作树做。FF 候选与拒绝信封施工已收口到 main；短请求旁路只动 CLI 末端和独立模块，与 F4 持久作业及 Dashboard 候选文件分开。StockWiki、IQS、Dashboard、StockQA 继续归现有工作线，当前不派重复卡。
- F4 的进程领取时机仍有一处恢复缺口。外层宿主 worker 先把动作从 queued 记为 running，随后才进入实际执行或另起 owner runner。若外层在两者之间退出，只有声明的 running，没有原生启动，恢复会永久保留未知并占住工作区。计划把现有的原子领取移到实际执行进程一侧，保留已领取或历史不明时的保守恢复。用实际子进程突然退出证明恢复前后原生启动数。

- F4 RF/Audit 新问题：财报从本地复用属于原件结果，`latest_as_of` 的元数据职责可能已经访问供应商。RF 旧布尔值把两者合并，导致中断后可再派及费用未知被当成零。修复后的恢复按原作业和尝试查找，Audit 原报告 SHA 防止同号发现被改写后继承旧复验。见[原生与宿主验收](f4-rf-audit-acceptance.md)。

- [M3 验收](../module-boundaries-2026-11-11/review/m3-formal-t3-20261116.md)记有真实限额遗漏、候选证券身份缺失、供应商启动前的 Windows 临时目录写失败和预期损坏件拒绝。一次高层失败可涉及数个责任，一种失败字样也可指向不同修法。
- [共享读取预算](../module-boundaries-2026-11-11/review/cwp-cn-issuer-read-budget-20261115.md)说明 36 份文档约 126 MB 由重复的 64 MB 截断。应复现合法输入与真实预算耗尽的两面。记录预算 owner 和供应商是否开始，费用未知不能补零。
- [P1 原文视图](../du11-source-closure-2026-10-18/review/p1-business-quote-view-20261116.md)已证明指定四处引用能保留冻结检查点。自动选材、全新生成及 RF 消费仍需各自运行。将问句借给答句、遗漏股东信息来源、丢失建设条件都是退出成功也能查到的错误。
- [既有 I08](../module-boundaries-2026-11-11/interfaces.md)把诊断与业务终态隔开。FF 有持久 job 和关联 ID。ET 在选用的 stderr 协议中报告用量，SID 错误回复也占有固定输出通道。反馈旁路要兼容这些通道。CWP 的 AUTO outbox 属于来源生产；固定公司抽样、预算和四路审查沿用 Audit 的现有责任。

- 2026-11-17 只读普查发现 RF 有 9 个并行本地提交和 3 份在改运行资料；QA、IQS、Dashboard 都有活动项目；MeetingConverter 有 `.coverage` 修改。ET、SID、IR 状态和写范围适合独立实现。计划只追加归属清楚的模块文档。

- F3c 的真实响应证明合法引用和正确数量仍可能遗漏业务范围。独立反例表明同一数量也可能来自经销商、集团、否定或计划，自动回到原文需要局部主体、语态和完整改写对齐。分红、纯比率和样板陈述的修理归自动业务视图，带经营说明的混合来源保留原样。 [保存响应和三市场对照](f3c-saved-response-acceptance.md)

- 2026-11-18 F2 独审反例纠正了三类容易漏过的边界：SID 的 CLI 包依赖漏带、不同期次 ID 合并与宿主缓存污染夹具；IR 将待写内容误作已发布内容、诊断计算逸出；ET 旧测试把损坏的可选收据当许可门。组合按本仓输出读回，27 个唯一观察中 24 项符合预期、2 项未知、1 项受控偏差，重放不重复。强制终止只有开始记录时仍需以原生作业查账，归 F4。[具体验收](f2-owner-acceptance.md)
