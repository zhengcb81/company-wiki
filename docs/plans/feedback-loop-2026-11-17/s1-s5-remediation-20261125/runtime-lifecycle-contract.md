# 运行生命周期与公开边界

## 记录归属

运行入口先确定可从调用者取得的原运行号和当前尝试号。复用所属模块当前公开的作业、请求或相关号；子步骤通过显式字段关联父运行，历史尝试继续可查。外部下载、模型请求、子进程以及 HTTP 流响应开始前，记录已经掌握的输入引用和阶段。可信的业务回执先提交到所属模块。对正常、失败、拒绝和中断保留同一次运行的阶段事实，记录时间、实现版本、脱敏输入引用、原退出或返回状态与可读原因。缺失的事实表示未知。

调用者沿现有公开查询得到原尝试状态、关键阶段、有权限读取的原因或明确不可读状态。跨仓通过所属模块公开接口消费；可以用仅实现公开协议的替身验证。纯帮助、能力探测和回读本身不再触发投递或业务执行。仓内使用已有账本、轮转日志或恢复载体，按可复现的运行行为验证。优先复用现有状态根。

## 恢复与降级

- 已知未启动、可能已经发起、已收到响应及已确认落地分别表达。响应正文后续失败不证明请求未发或费用为零。重复查询和恢复按原业务键对账。
- 每次尝试拥有独立的在途产物。恢复先判断原进程与外部效果。由所属层决定发布哪个已确认结果。迟到的旧尝试不能覆盖已发布产物，也不丢历史。
- 业务终态、已有费用和诊断投递分别保存。附属日志失败保留业务原结果。已有诊断丢失或无可写介质时，沿同一运行号报告降级状况。使用机读 stdout 的入口，告警使用可安全脱敏的其他通道。
- 凭据、原始子进程输出、配置值及不可公开的原文在写入任何日志前脱敏或仅存安全引用。诊断耗尽或出错不触发新一次下载、付费请求或业务尝试。

## 回归与独审

各仓选择独审中的真实公开入口。覆盖一次正常运行、可控原失败、新进程按原编号查回、重复查询零副作用。再按实际风险选用进程强停和迟到写入、单/多日志介质故障、合法路径变体、截断响应或分页错误。需要重试的路径使用离线替身验证次数。每仓日常测试覆盖其已证故障，运行平台行为用本机验收。独审按实现候选的实际文件或提交重跑主要验证，并检查状态与依赖的归属。
