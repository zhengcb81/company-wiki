# R4 迁移表：保留原始成果要求，退出不必要的共同前置

日期：2026-09-07。状态：**PLANNING_ONLY / NOT_IMPLEMENTATION_AUTHORIZED**。本表只调整计划归属与先后关系，不宣称完成产品修复，也不授权启动 worker、处理真实数据、下载、外发、删除或自启动。依据[虚拟数据湖诊断](../data-lake-simplification-2026-09-07/README.md)以及 R3 总计划、三份执行手册；本表与 R4 活动执行文件一起取代 R3 的强制编排。R2/R3 既有审查只绑定当时文档，不自动签署 R4。

## 1. 只保留四个增量和一条独立业务轨道

- **A：统一本地读取合同。** 用户按公司、报告类型、期间、版本及所需能力请求。定义本地查询、原文打开、联网更新和加工请求的明确差异；普通本地读零网络、零写、零 worker 控制。
- **B：位置透明的存储与索引。** 获准 root 同等可读；内容、逻辑报告和物理副本分离；存储层选择健康同版本副本并负责读取完整性。目录优先级只影响 I/O 选择，不决定身份、期间或事实可信度。
- **C：消费者瘦身与唯一 producer。** filing/revenue 依赖来源引用和能力，不依赖特定目录、上游角色 DAG 或 pause/resume。缺失下载或加工只经显式 request 交唯一持久任务入口；producer 负责其内部依赖、尝试与恢复。
- **D：安全运维收尾。** 修回收、取消、性能及失败恢复；获批后真实有限放量、自然观察、兼容退出。只约束相应写入、长期运行和迁移资格，不成为普通读取的前置。
- **M：收入业务独立轨道。** 资产事实和 export、单位/权属/内部流、generator、发布事务、历史回测与 confidence 保留；这些真实缺陷不因简化取消，也不阻塞 A/B 原文读取能力的独立验收。

依赖只按实际接口：A 的读取合同确定后做 B；C 消费 B 的合同与已验证读取实现。D 中安全设计和 M 的设计/纯逻辑修复可以并行准备，不等待全体完成。C 的真实加工试验必须先满足该动作必要的安全/隔离条件；**不能把 C 整段完成设为 D 安全能力测试的前置，又把 D 整段完成设为 C 前置**。生产 worker 的恢复始终需要对应安全、性能、真实运行资格和当前授权；自然观察与收入模型不反向阻塞 A/B。

## 3. 七项减法必须同时满足的保留条件

| 可删/合并项 | 先证明什么，才允许实施删除 |
|---|---|
| 消费端 root 名称/物理路径分支 | B 的同版本健康副本、根撤销、OS 不可读、越界和读时替换测试通过；消费者保留来源身份/内容版本/locator，不依赖诊断路径 |
| 多处权限解释 | 单一注册与操作能力合同已接全部实际入口；缺配置/未知版本明确失败，不默默降级到 companies；读取许可不能推导写/外发许可 |
| 每仓整文件重复 hash | 真实 open 的稳定只读流/快照和完整性信任边界经独立审查；测中途替换与同 size 修改；保留必要跨信任边界复验，不只删除 hash 获得快数字 |
| 下游上游 DAG/两套队列 | 唯一 producer 的持久请求、崩溃/重试/幂等/实际 attempt 和消费者所需产物已真实闭环；未完成任务可见，不静默丢弃 |
| 取资料 pause/resume 与薄 subprocess | 无写 query/open 从未控制 worker；有写改为唯一写者/短事务等已验证替代；隔离真实并发测试通过后再删保护，不能先删再赌 |
| epoch/cohort/shadow/bridge 等迁移分支 | 区分“临时迁移 cohort”与“真实写/外发精确 scope”；前者有调用者清单和退出试验，后者不能一并删；未知消费者保持明确待迁移而非偷偷复活旧路径 |
| 95 个旧计划门及其大 DAG | R4 保留阶段独立设计/接线/测试/验收和高风险动作批准；旧 gate-dag 与校验器只作为 R3 历史，不再驱动 R4；本地数据读取无需查询审查收据 |

## 4. 防止“减法”变成缩目标的验收规则

1. [unit-ledger](unit-ledger.md) 的 **117 项**、[GP](gp-audit.md) 和 [legacy 继承](legacy-inheritance.md) 仍是原始目标索引。实施时每项填 R4 主归属、原 finding/RED、所需真实层级、结果或明确 pending 原因；一个旧目标拆多阶段时必须保留全部子结果，不能挑已绿子项整项关闭。
2. 本表只建立 WP 级完整迁移，不是假称已经完成逐 117 项的当前产品复验。原红例、失败历史、冻结计划、签署收据原字节不改；R4 新结果绑定当前输入，不能继承旧 review 为当前通过。
3. 两种四根证据不同：同一真实 PDF 的隔离四副本用于**位置等价实验**，可以证明与目录无关；四个真实既有 root 各自原材料用于**实际覆盖验证**，不能把同一个 companies 副本复制四遍冒充原覆盖目标已完成。第五根实验只需支持格式的注册变化，不得修改消费者。
4. 真实 E2E 用真实原文、真实生产入口/存储/进程和独立 oracle；正向链不得 mock、预拼 pages、手写 completed、复用一公司改名、改模板结构。故障注入/合成规模单列机制证据，不算真实 provider、真实 49GB 或自然运行。缺数据/权限/工具为 blocked，不降级成 passed。
5. A/B 可独立交付“获准根上已索引原文位置透明读取”；C 可独立交付“显式加工与真实复用”；D、M 保留各自未完事实。该分层减少错误共同前置，**不是宣布整个原始项目已经完成**。
6. 每次阶段审查先问：增加的是必要能力还是重复概念？删掉的是实现冗余还是原始安全/成果要求？新增 root 是否仅注册，普通读取是否零写/零网络/零 worker 控制，消费者是否零特定 root 业务分支？任一答案不明，停在设计审查，不靠多加门掩盖合同不清。

本轮未运行任何上述产品测试、真实 E2E 或副作用操作。后续执行使用 R4 当前执行文档；旧三份手册只作反例与细节素材，不继续叠加旧依赖。
