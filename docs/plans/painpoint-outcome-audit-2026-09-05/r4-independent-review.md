# R4 独立计划审查

日期：2026-09-07。审查 agent/task：`/root/r4_transition`（独立于两份被审文件的主实现/编写者）。审查范围仅 [simplified-execution-plan.md](simplified-execution-plan.md) 与 [simplified-test-matrix.md](simplified-test-matrix.md)，完整阅读。本人编写的 r4-transition.md **不在本次独立签署范围内**。本轮没有修改产品、运行产品测试或真实 E2E；这是计划可执行性审查，不是产品验收。

## 初次结论：changes_required

四增量加独立收入轨道的方向合理；常规三次独立决策明显少于原逐 WP 六门。读取与外发分开、健康同版本副本、真实资料与独立 oracle、未知状态不伪造成功、D.SAFE 非统一通行证等约束写得清楚。主要剩余问题是**测试层级没有明确对应各个决策**，弱模型仍可能由一句“所有 required”重建原来的互等。

### P1-R4-01：VR 的“全部 required”与真实 AR 的准入互等

- 证据：测试矩阵第 6 节要求 VR 在第二隔离环境重跑“所有 required case”；P06 包含真实三市场下载/修订，P08 包含 1→3→7，O07 包含真实调度和自然时间。执行计划 C09 又要求本候选隔离验证/安全/授权后才进行这些真实动作；C/D 准入使用 C.VR 等未区分层级的决策。
- 推理：若弱模型把 C 的 P01–P08 都当 C.VR required，就会等待尚未允许执行的 P06/P08；若将 O07 算 D.VR required，会在候选验证之前等待自然观察。解释成“先做真实动作补 VR”则越过本计划自身安全准入。
- 必须修改：逐测试组明确“VR 隔离机制/真实本地部分”和“AR 真实外部/放量/自然部分”；VR 只验证前者，不以尚待 AR 执行形成的结果为前置。外部/自然部分仍 required，但未运行只阻断该对应 AR，不得删除、默认 N/A 或假称通过。阶段内部 DR→实现→VR→获批真实动作→AR 单向前进。
- 计划验收检查：从 C.VR、D.SAFE 和一次真实 worker 准入向前追依赖，不能到达自身 AR；仅完成本地试验不能使 P06/P08/O07 显示 passed。

### P2-R4-02：C.local 的验收范围仍混入 P04 的真实 worker

- 证据：C 小节允许 C01–C04/C08 本地路线先交付；C08 引用 P01–P04，但 P04 本身包含真实队列、恢复及“真实 worker 用真实 PDF 加工”。正文未正式定义 `C.local.AR` 与其 case 子集。D 处“持续上线取 C.AR”也没有限定具体被上线能力。
- 推理：这样会使本地瘦身验收误等 worker，或把本地验收当作队列和真实外部链通过；笼统 C.AR 还可能使只跑本地 parser 的持续任务错误等待三市场 provider 验收。
- 必须修改：定义 C.local.AR 的精确只读子集（L/P01/P02/P03 的相应本地部分），显式不含 P04 worker、P05 有副作用、P06 provider、P08 放量；机制/加工/外部 route 分别记录证据资格，不另造大 DAG。D 持续运行只要求该任务实际使用路线的真实 AR，未使用能力不冒充已验，也不作为无关前置。
- 计划验收检查：worker/provider 永久未授权时仍能完成 C.local.AR；C.local.AR 单独不能批准任何 worker/provider 或自然运行。

### P2-R4-03：九源 broker/HTML 的 owner 应回到 C 的解析能力

- 证据：M08 唯一集中列出真实 7 PDF + 2 HTML，而 C09/C10 只引用 P04–P08 并分本地/加工/provider 签收；M 节明确为收入业务独立轨道。
- 推理：broker/HTML 是资料生产系统本身的原目标，不是必须等收入模型才检查的能力。若只放 M，C 可能在九源解析缺口未体现时签“真实加工完整通过”，又把剩余问题推迟到无关业务轨道。
- 必须修改：保留 M08 测试 ID 也可，但声明其主归属 C.parser，M 仅消费所需结果；C 的具体 parser AR 必须包含适用的九源真值/缺口。基础原文读取仍不等它，矿业 M 也不强制等待不使用的 broker 来源。
- 计划验收检查：原 7+2 不足明确阻断该 broker/HTML 能力完整签收，不影响原文位置透明的独立验收。
