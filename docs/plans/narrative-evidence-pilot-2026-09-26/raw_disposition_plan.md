# 不重要来源的判定与逐文档原文回收（D0–D5）

> **2026-09-28 当前执行范围校正：**用户最新边界是原始文档不丢。按[跨仓总计划](cross_repo_mainline_and_delivery_plan_2026-09-28.md)，本轮 G-D 只处理可重建派生；以下 D1–D5 关于唯一低价值 raw 和同 SHA 原文副本删除是历史提案，**不在当前实施队列**。恢复 raw 删除前须重新确认当时用户意图、项目级规范和读/导出合同，不得凭本卡旧授权执行。

> **PLAN ONLY。** 本卡修正“跳过切片但总是保留 raw”的假设；不运行删除、迁移、Worker 或生产数据库写入。它只设计 company-wiki **拥有的**旧原文和派生文件的回收，不删除 Dropbox、dayu 等外部只读输入根的文件。46.266 GiB 的共享 SQLite 主文件按[提前退役 F0–F5](early_catalog_retirement.md)独立处理。D0–D5 是实现步骤，**只在 [G4 冻结批次](milestone_review_cadence.md)集中审查**，不逐卡签字。

## 1. 已核对的边界

- 现有 `SourceManifest v1` 保存 `original_path`、原文 SHA 和 `immutable_status=verified|quarantined`；`verify_file()` 要求该路径上的文件仍存在且字节完全相同。它**没有**“按政策已删除原文”状态。直接删 raw 会使旧校验报 mismatch，也会让检索、预览、旧 locator 和下游文件复用产生误导。必须新增版本化的来源**可用性/处置记录**，不伪造旧 manifest。
- 项目现行 `AGENTS.md` 把 immutable raw 列为上游事实来源。此卡是用户提出的**策略修订提案**；正式 D1 必须同步修订该项目级保留规范，明确“保留源”与“经 D 卡处置源”的定义、权限和审计责任，不能让实现者仅凭本规划文件绕过现行约束。原始 SHA/manifest 保留为历史身份；删除后不再声称原文可回读。
- 现有 `skipped_no_narrative` / `skipped_event_notice` 仅表示不产出业务切片；它不证明原文无任何检索、追溯或历史价值。`retired` 也只表示来源版本状态，不等于内容无用或可删除。
- 生产 catalog 的 `locations` 只读分组中，`company_raw` 的 `original_primary` 有 active 7,524 件、`observed_size` 合计 6,511,169,498 B；retired 9,046 件、合计 18,641,858,464 B。**这些是曾观察的逻辑大小，不是目前仍存在、仅占 C 盘或可删除的实际字节**。先逐路径 stat、核卷与所有权，再估算真实收益；不得按状态或这些合计批量清理。

## 2. 每个 source 的两种独立裁决

| 内容处理裁决 | 原文处置裁决 | 行为 |
|---|---|---|
| `selected` | `retain_raw` | 保存可回读的原文，生成选中证据/摘要；旧重复位置可另按同 SHA 清理。 |
| `skipped_*` | `retain_raw` / `hold` | 不生成业务切片；原文仍可检索/预览，或待覆盖/消费者审查。 |
| `skipped_*` | `duplicate_reclaimable` | 另一位置存在 SHA 完全相同的可恢复 canonical 原文，旧位置无路径依赖；逐路径删除重复副本。 |
| `skipped_*` | `irrelevant_reclaimable` | 唯一原文经完整覆盖、独立复审、保留规则和消费引用检查后允许处置；删除后只留来源身份/处置 receipt，全文与原文引用明确不可用。 |
| 任意 | `blocked` | 无法读完、OCR/表格不透明、身份/版权/保留期/所有权不明、有下游引用或竞态；不删除。 |

**默认保留规则**：年报、半年报、季报、招股/再融资/可转债、投资者关系、电话会、研报可能在正文、附录或业务表中有独特叙述，不得仅凭文档种类、标题、旧 `retired` 状态、模型一句“无价值”或未选出切片删除整件。制度、会议通知等负例也须检查全文/附件、业务表、OCR 缺口和跨公司用途。确定性同 SHA 重复副本可优先清理；唯一低价值原文先做可审计小批量试点。未完成覆盖检查时可跳过昂贵的业务摘要，但处置状态只能为 `hold/retain_raw`。

## 3. 处置资格与兼容合同

一份**唯一**原文要进入 `irrelevant_reclaimable`，必须同时满足：

1. 来源身份和文件身份锁定：`source_id`/SHA、字节数、所在卷、绝对路径、root、文件状态一致；路径由 owner root 下解析且不是 symlink/junction/reparse 跳转；当前文件在分类后未变化。
2. 结构覆盖完整：PDF 页/表、附件和 TXT 全行都已检查；OCR 失败、加密页、无法解释的表格或未知内容形成 `blocked`。对业务候选执行细读，负例理由定位到页/行；G4 审查者分层抽检普通负例、全审高风险/异常件与首批唯一原文处置理由，不逐件重读全文。不得因只抽首页、目录或关键字未命中而宣布整件无价值。
3. 证据与消费者无依赖：无选中证据/摘要/仍有效旧 span 的可用引用，无全文搜索/预览承诺、人工 pin、StockWiki/revenue-forecast 等文档证据消费者的原路径或 source 引用需求；invest-quick-scan 的 optional identity mapping 不构成原文或叙述证据引用。历史 as-of 和 retired 查询有显式处置语义。若旧 active-only DB 仍含这份来源的 span，读路径必须先识别处置记录并拒绝把它当可回源证据，待后续批量紧凑重建才移除旧行。
4. 保留政策允许：来源获取许可、用户锁定、版本替代关系、预注册观察期与可恢复性等级已核实。唯一原文无独立副本时，物理删除**不可由 SHA/URL 保证恢复**；审查 receipt 必须写明此损失及批准范围。重新下载若字节不同，注册新 source/version，不能冒充原 SHA。
5. 只处置本项目拥有的明确路径；外部只读 root 仅记录建议，不由 company-wiki 删除。`SourceManifest v1` 与必要的 sidecar/来源元数据保留为历史记录；新增 `SourceDisposition/v1` 覆盖 `raw_available|raw_relocated|raw_disposed_intentional|raw_missing_unexpected`、原因、策略/模型版本、覆盖摘要、审查者、旧/新位置、处置时间、删除 receipt/hash。查询、预览、filing-fetch 与只读 export 要区分“按政策处置”与“意外丢失”，绝不能返回假的空结果或仍宣称原文可回读。

## 4. D0–D5 可执行卡

| 卡 | 工作与证据 | 放行/停止条件 |
|---|---|---|
| **D0 真实盘点** | 按 owner root/卷、source SHA、所有 locations/aliases、文档类型与状态逐路径核存在、硬链接数/大小、raw/sidecar/derived/旧引用；汇总实际可回收字节，另列外部 root。 | 仅用 `observed_size`、`retired` 或目录通配符估算或删文件即停。 |
| **D1 处置合同** | 正式修订项目级 raw 保留规范；版本化 `SourceDisposition/v1`、不可变 source ID 与历史 manifest 的关系、状态转移、查询/预览/export 的 `raw_disposed_intentional` 响应和重新获取规则；三方消费者合同测试。 | 规范与新合同未获审查、旧 `verify_file()` 的失败仍会被误报为源损坏，或旧 span 仍可被当成已验证证据，即不得删 raw。 |
| **D2 负例验证** | 用 P09/P10 和各类混合正例、招股/再融资业务表、IR 问答、季度财务表同页业务段、OCR/附件反例建立完整覆盖与人工复核；冻结分层留出集并单列“误删高价值来源”指标。 | 误删反例、未读范围、只有模型自评或不满足 W0 预注册统计门槛，则 `blocked`。 |
| **D3 候选清单** | Worker 只提出 `retain/duplicate/irrelevant/hold` 与证据，不执行删除。生成每件的 source SHA、绝对路径、卷、字节、身份、原因、覆盖、引用扫描、保留期、预计节省、回滚方式；G4 对冻结小批量 manifest 一次审查。 | 身份、所有权、引用或风险接受缺失的个别来源留在 `hold`，不拖累批内安全项。同 SHA 多位置须证明删后至少一份可恢复 canonical 副本。 |
| **D4 逐路径处置** | 独立单执行者在持久日志写 `delete_intent`；持锁重读精确路径、卷、大小、mtime/文件身份、在途解析、引用和策略版本，并对每个待删文件在此时**只做一次完整 SHA**与冻结身份比较；按精确绝对路径删除、核不存在，追加不可覆盖 receipt。旧 derived/index 随批次按依赖清单处理。 | 路径/身份变化、hash 不符、外部 root、正在解析/引用、删除后读合同未切换即停。绝不递归删公司目录、批量删 `raw/` 或把共享 SQLite 当逐文件产物。 |
| **D5 恢复与复盘** | 崩溃后重放：有 intent+原文仍在则重验再执行；有 intent+原文已不在则核确切路径/文件身份/receipt 并标记或人工调查；无 intent 却缺失是事故。比较前后同卷真实已用字节、检索状态、下游合同，按规则版本变化重审旧 skip。 | 无法解释缺失、引用失效、节省未兑现或发现漏判业务资料则停批次；可从备份恢复的来源按 hash 恢复，无法恢复的唯一来源明确记录损失。 |

旧主库 F0–F5 可先释放主要的 46 GiB；D0–D3 可以只读并行准备，D4 必须等来源处置合同、旧/新读路径和消费者通过验收。D4 之后积累的旧 DB 空页不会按来源变成磁盘空闲，按批次再做受控紧凑库切换。Worker 多文档并发只负责**提出候选和建立证据包**；删除单执行者、逐来源序列化，不能与同 SHA 的解析/导出并发。

## 5. 必测反例与验收账本

- 同 SHA 双路径删一留一；不同 SHA 的“同名/新版”不得当重复；旧路径已被下游固定引用；外部 Dropbox/dayu 路径；Windows junction、符号/硬链接与路径大小写；分类后原文改动。
- 标题像通知却在附件含业务进展、P08 式大表格中的 IR 问答、P04 式业务表、季报同页财务表与业务段、扫描件 OCR 失败；这些必须阻断唯一原文处置。
- 删除前/后崩溃、磁盘满、删除失败、旧 DB active span 查询、source 再次出现、策略版本变化、重新下载字节不同、retired/as-of 查询、filing-fetch 复用及三方只读 export。
- 每批账本分别报：候选/保留/阻断/删除件数，抽检与盲测分母、误删反例，原文/derived/索引/DB/备份**同卷实际字节**，删除 receipt 和无法回源的来源数量。P09/P10 通过“零业务切片”测试不等于通过原文删除测试；后者须另验。
