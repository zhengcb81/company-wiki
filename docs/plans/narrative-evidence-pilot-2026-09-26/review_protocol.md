# 自动化验收规则

> 2026-09-29 当前跨仓节点名和独占 owner 见[并行总计划](parallel_harness_orchestration_2026-09-29.md)；旧 G0–G3 名称只标识早期测试类别。具体人工门禁删除顺序见[统一清理方案](gate_and_contract_simplification_2026-09-29.md)。

> **2026-09-28 生效。** 用户要求取消过多人工审查。本文件取代旧版“审查、放行与回滚规程”中的 reviewer、逐项签字、review receipt 和人工批准要求。实施依据是自动测试结果与数据完整性断言；无需另找 reviewer 或等人工签收。

## 规则

- 日常改动只跑受影响的单元/合同测试和 diff 检查。
- G0–G3 大节点各跑一次对应真实数据 E2E。只重跑受变化影响的测试；复用其他仓库同版本、仍有效的测试结果，不重复签收。
- 每次运行自动记录仓库 HEAD、命令/退出码、测试数、样本和原件 SHA、隔离目录是否恢复、关键费用/字节指标。无需另造 YAML reviewer receipt 或逐卡报告。
- 用户已经授权已配置来源交给外部 LLM。不要设置 private/public ACL、逐文档授权、prompt review receipt 或 prompt injection 人工扫描门。仍核验 source hash/lineage，并把文件正文作为不可信数据输入；结构、来源引用和职责边界由自动校验器验证。
- 对准确公司/期次的采集请求，匹配期 transcript 自动作为 companion。先复用已有原件；只有明确请求且本地未命中时才调用工具。无需逐期或逐文档再次批准。
- 原始下载文档全部保留。只允许清理已证实可由 raw 重建且无消费者引用的派生产物；路径、身份、引用和字节差异由清理器自动校验，不设人工批次审批。

## 自动停止条件

以下任一条件触发时，自动暂停受影响对象/能力并留下可读错误；不扩展为全项目人工审批：

1. 来源身份、期次、原件 SHA、派生 lineage 或 locator 校验失败；
2. 输入或输出超过已配置的字节、文件数、并发或费用上限；
3. 测试试图写入生产数据根、改动 immutable raw，或测试结束未恢复隔离目录；
4. provider/API 明确拒绝请求、凭证缺失或接口不可用；
5. 已有唯一产物出现同 key 不同 hash，不能安全覆盖。

修复后只重跑失败测试及直接依赖。provider 不可用时，代码用 fake/replay E2E 验证，并明确记录未验证真实连接；其他本地/离线工作继续。

## 大节点自动测试范围

G0 验跨根读、SourceRef/locator 和现存引用；G1 验代表性年报/半年报/季报/招股与再融资/IR/TXT 到选择包和引用定位；G2 验 StockWiki/RF 真实消费、并发任务恢复与费用上限；G3 验可重建派生清理、原始文档不变、净空间变化和路由回退。具体用例和运行目录按跨仓总计划与端到端测试计划执行。
