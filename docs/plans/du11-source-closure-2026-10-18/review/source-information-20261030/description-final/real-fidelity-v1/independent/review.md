## 三项剩余共因与严重度

### NL1 · P2 · 确定错误：当前行动被标成计划

原文是“公司积极开发国内市场，持续完善国内市场战略布局”，没有“将/拟/计划”。t1-1 的 planned 将正在做的行动降成未来计划。正文没有新增业务事实，错误在结构化状态；同一输出 t8-1 又将“积极布局”标 actual，说明当前行动与计划的粒度尚不稳定。

共因是提示突出 completed actions 与 future intentions，却没有同等明确地覆盖**已经在实施、尚未完成的 actual ongoing action**；有限 guard 主要检查未来被改 actual，未覆盖这个反方向状态错误。下一节点应使用跨行业、跨语言的当前实施/未来计划/目的对照，不能要求行动必须完成才能是 actual。

### NL2 · P2 · 确定缺失，后果属于独立条目上下文风险

同一原文 support 为“根据公司控股股东中国节能信息，中国节能与宁德时代已经建立了联系，并希望建立业务协同与合作”。t6-2 保留了转述源与参与方，t6-3 独立条目却只剩“中国节能希望建立业务协同与合作”。缺字是确定的；没有证据表明模型虚构了签约或已合作，所以不升级为 P1。

**归属限定的通用根修尚未完成。** 拆分 modality 时，原句中支配后续并列愿望的转述来源、意愿主体与合作对象也必须随命题携带；不能只把它们留在前一条。不能由此推成宁德时代已确认共同意愿或发行人已有合同。

这里也不能把“据股东信息”机械复制到同一 support 的所有子句：开头“公司现无生产VC”是发行人自己的否定，位于这段转述支配范围之外。下一节点要绑定实际支配范围、参与方与条件，而不是全段关键词补齐或公司专用补丁。

### NL3 · P2 · 项目设计产能的独立参数使用风险

t8-2 忠实保留“2025启动建设项目”“该项目包含约751吨/年”。**它没有说投产，不能指控模型已宣称751吨/年已经投产。** t8-3 也保留了建成后条件。

剩余问题是单个 actual 标签混载实际项目启动与项目包含的设计产能规格，数量本身没有独立的规划/项目阶段口径。RF 或其他消费者不能因 actual 就将它作为现有出货量、产量或已投产能力。

下一节点应把项目事件与数量口径分开：已启动事件是 actual；设计/规划产能仍是项目规格，保留相应建成阶段条件。还要区分设计产能、现有能力、产量与出货，不能只按单位“吨/年”互换。

## 相比旧版六条，真正改善了什么

- t3 完整客户链和 t7 已售清单/开发数量，过去**已经供给模型却被遗漏**，本次得到保留。新旧八项 factual support 逐项相同；t3/t7 的 reading band 从 description 改成 meaningful_fact。
- t2 的新闻来源和投资者前提回到正文，且否定保留“重大”；旧版这个具体归属错误已解决，但 NL2 说明不能扩大成通用归属问题全部解决。
- t4 的收到、申请中止和条件性未来申请清晰分开；t6 的当前否定、股东联系与愿望也拆分。t8 的建设启动和建成后未来结果分开，但项目数量口径仍有 NL3。
- 20 条主要是对原有命题进行拆分，并不是新增20个业务事实。新增条目还暴露了 NL1，不能单靠条数增加评价质量。
- 这是同一开发样本上的各一次真实调用，prompt、阅读值与输出计划同时改变；不能隔离每项改动的因果贡献，也不能当作 holdout 泛化验收。

## 程序质量与流程必须分开

本次 bundle 的 selection 仍是 **partial**、coverage_complete=false：229 个候选中选中15个 spans。8/8 selected tasks 不意味着读懂了整份 IR 的所有信息。

`summary_assessment` 正确保留 semantic_status、subfact_coverage_status 均为 **not_evaluated**；known_constraint_status=no_known_violation、diagnostic_count=0 只是没有命中有限规则。三条 P2 的 machine needs_review 都为 false；全局 needs_review 来自 t2-1 的 uncertain。**全局有 review 标记，不等于这三处风险已被识别。**

`local-guard-probe.json` 记录三条实际 claim 均没有有限 guard 诊断。另一个明确标为合成的“已经投产”反例会触发 possible_modality_mismatch，说明不能把“未提示项目参数口径风险”误说成程序连显式假投产都完全不查；该合成句**不是真实模型输出**。

真实运行已有1次 POST，输入6226、输出743、合计6969 tokens，费用代理1286 micro USD（不是发票）；activation 恢复及 same/cross-run 都没有新增 POST，原件/配置与清理记录通过。这些是工程过程证据，不能使自然语言质量通过。

原 run 的 overall FAIL 来自 consumer 字段类型不兼容，不是生成失败。ROOT 后续另存零付费 consumer 重放记录，body SHA 不变；本独审没有据此签消费者采用，也没有把它冒称新模型或新缓存实验。

## 可复查结论

`review.json` 包含全部20条真实文字、modality、质量标记、逐条判定、source span ID/locator/原文、八项 gold 结果、新旧比较和压缩/解压 artifact SHA。`local-guard-probe.json` 是只读局部诊断观察。

本轮没有改写 captured 输出、历史 assessment、gold、产品或已封工程报告。当前可交付的是：**两项关键遗漏和具体新闻归属问题在本样本得到解决，0P1；3P2与部分质量结论完整交付，通用归属、当前行动状态和项目数量阶段仍需下一节点根修。**
