## 根因与实施

- 原来 `document_understanding/decision_inventory.py` 实际同时组合 source/automation 算法，但放在下层 DU；其逐模块手写列表漏 antecedent、parent composition、route signals、strategy binding。
- 将组合 adapter 移至 `source_catalog/narrative_decision_inventory.py`；DU 原位置保留薄兼容重导出，历史 import 和 `_versions/_inventory` 工程夹具可继续使用。纯 `decision_dependencies` package 未改，继续不认识 source/automation。
- 新 `source_catalog/reading_recipe.py` 由来源组合 owner 声明阅读/PDF 前端 entrypoints 及算法边界；在该边界内递归追踪源码 literal imports（含相对、from-member 和常量动态 import）。新增 imported helper 自动进入闭包，未导入兄弟文件不进入。不是补四个模块名，也不哈希全仓。
- 非 PDF 排除 PDF frontend、geometry policy 和 PDF snapshot projection；实际 PDF 使用才加入对应入口及投影 helper 闭包。profile catalog 内容依旧按实际 family/matcher/used facet 记录，未变成全 JSON hash。
- 每个 recipe 中源码只读/哈希一次；AST 缓存按真实规范化源码 bytes（max256）而不是 mtime，因此修改同大小文件或规则-only 变化仍能识别。观察非PDF初版90模块、cold约1.1s/warm约0.13–0.15s；这是局部观察非性能验收。ROOT后续拆分的新材料/准入模块由 import 自动发现，未添加公司特判。
- inventory 组合器自身也绑定源码 SHA；原先即使其自身逻辑变动，只要漏升手工版本也可能错误认为 decision same。新增真实cache反例先RED，再修这一边界。
- `automation/narrative_generation.py` 仅切换到来源 owner 的 `current_decision_trace` import；ROOT另负责在 `narrative_reading.py` 切换 producer import。旧 inventory版本1.11升级1.12，不能冒旧 frozen trace 为本版通过。
