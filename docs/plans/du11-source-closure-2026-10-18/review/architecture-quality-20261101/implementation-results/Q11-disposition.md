# Q11：保留跨信任边界SHA，不新增可信许可标志（待独审）

Q10将公开export后端改为窄Protocol后，可以接入不继承具体reader的backend。由该后端返回的VerifiedContent能带正确ID/hash/长度、同时携带错误但等长bytes。新增真实替身反例证明：只有调用者对收到字节实算SHA才拒绝，字段一致不够。三个port用例通过3.14s。

存储磁盘读时SHA证明打开瞬间的源文件，公开backend接收时SHA证明实际收到的bytes，跨时间重新open证明当前源。这些位置有不同责任。以‘同进程’一刀切删除，需要新建可伪造的trusted标志/receipt状态或把纯DTO强绑具体类，会退回Q10反向依赖并增加复杂度。按原细则Q11‘按收益决定/收益小后置’，本轮选择保留此边界校验，不引入新的权限/信任注册。

补充有界内存微观察（不是生产基准）：2MiB不可变bytes连续16次SHA共0.0202147s，无文件、无模型/下载。此观察不能推广到所有源大小，但不支持为几毫秒删除接收端完整性或建立复杂capability链。实际主要浪费已经通过Q04全树扫描和Q03全库投影改造处理。

整改处置建议：RESOLVED_BY_BOUNDARY_JUSTIFICATION，非‘CPU已全部消除’。保留source metadata/identity各所属层、Q10减少实现耦合；未来若明确同一对象在同一可信owner内反复hash成为测得热点，再做局部缓存，不跨公开端口绕验证。需独审认可后更新总表，不自行标全通过。
