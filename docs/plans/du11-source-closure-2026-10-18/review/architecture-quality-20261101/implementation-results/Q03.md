# Q03 — 精准来源候选投影根修（READY，待ROOT集中独审）

## 已实施

- `_candidate_pages` 不再枚举全库同类文档：请求归一化 token 加既有 resolver issuer-alias 权威的同发行人 token，交给 catalog 候选 owner，最终仍由原 `_source_metadata/_entity_matches/_identity_matches` 与期间/资格 owner 决策。
- 新 `identity_candidates.py` 是派生索引，不是第二事实库。tokens 包含目录实体、legacy acquisition/dayu_meta 身份、verified assertion 身份及 source-fact patch 候选超集；保留过期/冲突候选让最终 owner 拒绝，绝不按原显示名称/目录或旧期间提前抹掉权威纠错。
- 显式 writer 事务内建立 tokens/dirty 两个小派生表，native SQLite triggers 标记相关变更，writer 同事务增量刷新。一个 source 的 assertion 影响所有引用该 source 的 document。普通 SQLite 维护写入不需要注册自定义函数；外部更新留下 dirty，readonly query 包含它们且不会刷新/迁移。
- token 索引是 (token,document_id)；精确选择使用 document_id 稳定 keyset 游标。每页一个 lookahead 区分正好 20,000 条 EOF 与实际截断；相关候选 20,001 仍给 candidate_budget_exceeded，没取消资源上限。
- 旧只读 catalog 没有派生索引时，使用 SQL 候选投影兼容；不在读时建表。首次后续显式 writer 才做一次全量 backfill，普通读/后续写增量。因此不宣称未迁移旧库已经获得完全索引性能。没有生产 DB 迁移或性能基准。
