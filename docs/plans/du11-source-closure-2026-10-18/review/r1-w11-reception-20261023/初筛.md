## 3. 两项共享根因，ROOT 接管修复

### W11-RC-01：条目祖先按标签类型而非距离选择（P2）

位置：`official_discovery.py:247–260`，关键为254行。

`_item_container` 声称最近 item，实际依次 `find_parent('article')`、`find_parent('li')`、`find_parent('tr')`。外层 article 包多个单链接 li/tr 时，先查到多链接 article 就返回 None，根本不访问更近的合法 item。日期、`_item_has_date`、Download 标题回补共用此 helper，因此是同一责任层根因，不是单公司漏词。

最小中性结构：

```html
<article><ul>
  <li><time datetime="2026-09-01"></time>
    <span>Annual Report 2025</span><a href="/a.pdf">Download</a></li>
  <li><a href="/b.pdf">Interim Report 2026</a></li>
</ul></article>
```

静态控制流可推导：a.pdf 留下但标题/日期回补丢失；未来日期无法用于排除；若链接是无后缀 `/download?id=a`，材料还可能整条漏掉。已有独立 article/平级 tr 测试不覆盖这一嵌套。

**ROOT 最小修法：** 冻结嵌套 article→li/tr 的日期/标题正控、未来日期反控及多链接共享 item 反控；一次选择最近原生 article/li/tr 容器，再执行单链接隔离。最近容器不满足时不继续上借日期；div 保持仅标题回补，不作为发布日期证据。复用当前 helper，不增加第二抽取器。

### W11-RC-02：已声明文档的内嵌载荷未检查且未标 unknown（P2）

位置：`official_discovery.py:342、349、489`；现有测试 `test_inline_declarative_script_is_not_dynamic_unresolved`。

代码只对 loading/外部 script[src] 记录未解决，再遍历 a[href]。以下声明无 anchor/src 时会完全未被检查，控制流仍得到 checked_index_only、空 limitations：

```html
<script type="application/ld+json">
{"@type":"DigitalDocument","name":"Annual Report 2025",
 "contentUrl":"https://ir.example/a.pdf","datePublished":"2026-09-01"}
</script>
```

完整 JSON-LD 抽取是新增能力；但对明确已出现、当前未处理的文档声明给出 not_supported/partial，是原卡“未知和不支持内嵌结构保持诚实”的责任。已有 Event+可见 anchor 测试本身正确，却不能证明该分支覆盖。

**ROOT 最小修法：** 先冻结明确文档声明、坏文档结构和非材料 Event/Organization 的中性正反例，再做有界声明性结构处理或明确 limitations；不执行 JS，不抓 script，不递归把任意 JSON 字符串当 URL，不将所有 JSON-LD 一律标 partial。本发现不证明缺失的药明真实 HTML 曾有这种内容。

两项已由另一独立静态 agent 复核；双方均未执行作者源码/脚本/测试，结论是控制流与原卡要求核对，运行 RED 由 ROOT 隔离工区完成。
