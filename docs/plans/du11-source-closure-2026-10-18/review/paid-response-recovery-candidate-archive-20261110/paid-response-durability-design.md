# Paid response durability: narrow owner design

Read-only investigation; no runtime change, test execution, PDF parse, provider/key access or API call. This is a proposed implementation seam, not a claim that present recovery exists.

## Recommended narrow wiring (one existing AUTO attempt receipt + existing object bytes)

1. Keep AUTO run/jobs/attempts/reservation ledger, existing workdir/object root, mother cumulative ledger and final artifact outbox. Add a small nullable typed paid-response receipt to the EXISTING `narrative_model_reservations` row by additive AUTO migration, with strict decoding in ReservationRecord; old rows remain absent. Do not add a second response-cache/task table, search-by-company cache, authorization JSON or duplicate body in result_json.
2. The receipt pins original paid attempt/run/job/request SHA, actual frozen generation/selection+task binding, adapter/model/prompt and protocol/decoder identity, byte artifact kind, logical object key, complete byte size and SHA, HTTP status and measured duration. Input/task binding is already part of request.input_sha256 and run frozen generation; use those authoritative values, no parallel binding manifest. Preserve separate outer-body SHA and final-content SHA meanings; never compare them as if equal.
3. Reuse LocalNarrativeObjectStore byte primitive through an injected bounded port, not NarrativeArtifactStore.prepare (bundle-only). Persist the exact outer HTTP body ONCE (no base64 envelope, second final-content copy or pretty JSON reserialization). Store small transport metadata in the AUTO receipt. JSON suffix on the logical byte key is not evidence that malformed content is valid JSON. No auth headers/key/request credentials are stored. The successful final content can be derived again by the pure envelope owner.
4. To cover the stated provider-read -> envelope-decode boundary, add one OPTIONAL transport completion sink invoked only after the bounded body is fully read, before `_response`. Caller supplies it only after admission. Sink fsyncs content object then attaches receipt to original reservation with idempotent compare-and-set. No DB transaction is held while network/file IO runs. Ordinary model fixtures may use final-content receipt kind; production HTTP path must prove outer-body capture, rather than falsely claim the old model-return seam covers it.
5. Persistence-sink failure must have a named paid-response durability outcome; current HTTP.generate catches OSError/ValueError as MODEL_HTTP_TRANSPORT. Do not let that broad catch disguise a completed-but-unpersisted paid reply as a fresh retryable transport miss. The original reservation remains charged/unknown, and a replay miss must not authorize a new POST.
6. Raw response publication is internal receipt recording, not a source/bundle effect. It must not create a public visible artifact/effect or replace a final summary. The existing final `verify -> effect -> dispatcher -> ACK -> activate` path remains responsible for source replay and visibility. This is reuse of artifact bytes/AUTO recovery, not a second cache system.

### Crash honesty / the unavoidable uncertainty boundary

A process can die after a provider charged but BEFORE any bytes are durable locally. Without provider idempotency/query support (not established here), that lost reply CANNOT be reconstructed or guaranteed0POST recovery. Preserve unknown reservation and report paid_response_unavailable; do not blind resend or claim success. Even temp bytes or a known SHA without a complete, bound receipt are not proof of a replayable response. The new contract guarantees0POST replay only once the complete response artifact+binding is durable. A partial read remains partial/unknown. Do not promise recovery at literally every CPU instruction following a remote charge.

Object-write-before-AUTO-attach failure can leave one small unreachable object; no new POST is needed while the same process can retry attach with known bytes. Across process death, do not discover an unbound object by guessing hash. A deterministic tiny attempt completion marker could close this attach window, but would add another authority and is NOT recommended for this narrow implementation: the conservative unavailable state is honest. If strict full atomicity of bytes+binding is required instead, use a bounded BLOB in the SAME existing reservation row, atomically attached with usage, rather than introducing a third persistence authority; assess that tradeoff explicitly before implementing.

## Proposed owner methods and replay ordering

Names below are proposed, not existing methods:

- `NarrativeRunStore.record_paid_response(run_id, paid_attempt_id, request_sha256, receipt)` attaches the bounded complete artifact reference idempotently, checking original attempt token/generation identity and scoped membership. A delayed original worker may record actual response/usage for ITS original reservation after lease expiry, as current settle_model_usage allows late usage; it cannot complete a job, decode into a current result or activate a bundle under the stale fence. This preserves money evidence rather than throwing away paid bytes because the lease expired.
- `NarrativeRunStore.paid_response_for_request(run_id, job_id, request_sha256, frozen_generation)` resolves only that exact immutable run operation; NOT an unrestricted cross-run/subject lookup. Before reading bytes, current active attempt/context must pass checkpoint and binding checks. Return original paid attempt provenance, never migrate usage to the new attempt.
- On replay, caller rebuilds the exact request/body hash, validates original run/job/task/model/protocol/selection/source binding, reads bounded object with size+SHA, reconstructs envelope through the SAME transport decoder (extract a pure replay entry with saved duration/status; do not pass a new monotonic start that fabricates elapsed days). It then idempotently settles original usage if a crash occurred after receipt attach but before usage settlement. Return model response for ordinary summary decoding. No new reservation or POST. Known receipt conflicts stay explicit; unknown usage stays conservative if parsing cannot establish paired counts.
- If same-attempt admission already exists, check its paid receipt BEFORE raising ALREADY_RESERVED. A new lease attempt must also find the same operation's original receipt before reserving again. A stale/missing/tampered receipt is a recoverability error with0POST, never a cache miss that automatically spends again. Existing retry semantics must explicitly distinguish known-zero/no-HTTP from charged/unknown prior requests.
- Current terminal failed job/history will not automatically execute decode again. Recovery needs a narrow same-run controlled retry/reset entry under existing AUTO transitions that preserves original attempt/charge and allows the ORIGINAL available protocol/decoder. Do not silently mutate immutable handler/generation to a new protocol. Old failed v4 bytes can be diagnostically replayed by old v4; they cannot become a valid new-extractive-protocol response or be promoted just because a new decoder is more permissive. New protocol execution is a separately bound operation within declared cumulative budget.

## Once-only money / fencing / storage

- Usage is charged to original paid attempt only; replay is not a new provider attempt. `settle_model_usage` identical receipt remains idempotent. Do not call `_settle` with the new attempt context while restoring the old paid response. Preserve unknown historical reservations; no budget reset/refund of uncertain charges.
- Distinguish total authoritative ledger snapshot from additional cost of recovery=0. Do not multiply historical HandlerMetrics when appending mother ledger; use existing reservation IDs/snapshots/dedup. Final output charge is separate and remains idempotent; do not replace output_bytes/output_sha256 with raw response storage values.
- Admission must reserve bounded RESPONSE SPACE before HTTP as well as money/tokens: actual configured max_response_bytes per finite batch + small receipt/WAL overhead, plus transient writer copy. Current defaults: HTTP body256KiB, final content128KiB; actual config wins. Final bundle output cap2MiB is NOT a raw-response budget. Count all planned focused batches, not one per document. Include bytes in existing BatchStorageBudget guard/object root, no unbounded complete history or duplicate response.gz+prefix+body archives.
- Reuse one content-addressed byte object per response; retry/replay stores pointer only. Refuse oversized input before object write/decode; detect truncated/missing/extra/tampered bytes before replay. Object hash is exact original bytes, not normalized JSON/text.
- Retain private paid artifacts at least through decode/publication and required retry/audit window. At final terminal compaction, an explicit bounded reference-aware retention policy can retire response bytes after final summary+usage receipt is durable; retain SHA/size/paid identity. Never eagerly delete the only replay copy while activation is pending or another attempt refers to it. No periodic raw clone or per-run full-source copies.
- Lease fencing guards CURRENT job/result/effect and activation. Original paid receipt/usage may be written late only against original immutable reservation identity; it cannot swap current result. Tests must include stale worker arriving after recovery and concurrent replays both producing at most one final effect/visible artifact.

## Minimal new RED controls before implementation

One concentrated loopback/in-memory source E2E matrix, no repeated PDFs/provider calls:

1. Complete HTTP return -> durable sink -> forced crash before envelope decode; reopen same AUTO/run, POST forbidden; exact raw bytes decode, original usage settles once, one summary/final activation.
2. Receipt written -> crash before usage commit; resume settles ORIGINAL reservation exactly once; unknown-to-known supported, conflicting late receipt rejected. Simultaneous replay/current stale completion cannot overwrite paid identity or final effect.
3. Model-envelope valid but summary decoder rejects (including >20 old reply): complete artifact remains, unchanged decoder reproduces failure0POST. Version/protocol/input/task mapping change rejects replay-as-new; no massaging old JSON into new result.
4. Decode success -> crash before handler finish; current lease recovery decodes same bytes0POST, then existing outbox crash/activation/same/cross-run cache controls continue. Invalid raw/final bytes never become public.
5. Missing/clipped prefix-only legacy record / object-write failure / attach failure / partial network body / hash-only row: charged or unknown remains, explicit unavailable,0POST. Historical full diagnostic prefix is only eligible for a one-time exact-byte import when independently proven unclipped+matching SHA/size+ALL original bindings, never generic automatic recovery.
6. Wrong run/job/request/body/model/prompt/adapter/selection/source/generation, tampered bytes, changed size, oversized payload, missing object, lease/generation race. Refuse before new reserve/POST; preserve existing source-current publication checks.
7. Configured finite batch count*response size preflight stops before HTTP when disk quota unavailable. Replay adds no full copies, no new output-slot or provider charge. Temporary files clean up; existing test lake/sentinels/config/original stat restored.

## Old incident limitation

The MiMo incident has complete5004-byte final content in diagnostics and SHA evidence, but it is NOT an existing durable response artifact protocol. It may support explicit read-only formal old-decoder diagnosis; any migration into an artifact must prove unclipped exact content and original binding, preserve old failed status/charge, and must not assert original outer HTTP body is reconstructible. General old rows with prefix/SHA only remain non-replayable. No new payment is authorized by this design document.
