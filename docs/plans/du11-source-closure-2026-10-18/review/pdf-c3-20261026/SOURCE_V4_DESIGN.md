## Diagnosis

The common defect is an inconsistent source contract, rather than eleven separate conditions. A locator-valid relation is treated as a complete business assertion in `source_support_use`; conversely `project_reading_business_fact` removes legacy dynamic reasons even when they represent an actual complete operating event. The purpose owner independently searches financial word pairs without resolving which predicate governs which object. Finally `scope_use` adds a second numeric test (newline plus any digit) over the authoritative table-shape observation. These paths can reject complete product/factory facts while accepting word fragments and reporting boilerplate.

Three properties must remain distinct: refs identify original characters; an assertion binds a real predicate to complete local arguments; purpose identifies what that assertion is about. Stage/attribution/modality are separate properties of a valid assertion. Unknown stage or actor attribution does not imply incomplete assertion. A noun or relative-clause substring does not become an assertion because an event regex emitted refs.

Concrete producer disagreement: for `The company acquired a factory. Right-of-use assets were recognized at carrying value.`, the direct reading fact is eligible with `operating_activity` and purpose operating. The production SourceOperatingSession yields purpose operating, empty relations and no reasons after projection, then `no_independent_business_support`. This is not financial-only rejection. The same loss affects new facility/plant events, capacity changes and passive channel service provision. No chapter-wide financial exclusion is appropriate.

Conversely saved actual `參與者」）；` has a relation with predicate `參與`, object `者` and no actor; `(ii) 經營租賃` has predicate `經營`, object `租賃` and outline marker actor `(ii)`. Refs are contained in the assertion range but neither establishes a complete operating statement. The unknown-ref bypass wrongly promotes them. The broader independent review also found incentive approval/vesting rules, audit engagement scope, forward-statement identification language, interim-period comparability disclaimer, going-concern basis and standards-adoption reconciliation. These require purpose of the governed assertion, rather than more isolated finance words or a whole-note ban. Real service/performance-obligation/delivery/billing mechanisms in the financial notes remain useful.

The saved product-release/platform scopes with C9a/X9a/Qwen3 have `has_unbound_numeric_cells=False`, purpose operating, empty relations and no eligible fact. Their product-code digits plus wrapping are independently turned into `source_numeric_scope_unresolved`. Removing that second numeric test is necessary but insufficient: the complete product assertion still needs the same shared proof used for ordinary names without digits.

## Minimal coherent owner change

Proposed expansion is the existing shared `operating_states/relations.py` and `patterns.py`, plus `source_catalog/narrative_operating_relations.py`, alongside the original four source files and owned test. ROOT should accept this owner scope before implementation. No consumer/compiler classification or new external wire version is needed.

1. **Shared relation owner: prepare and prove assertions once.** Reuse MatchingView, `_UnitScan`, `_classify_np`, `_bind_event`, existing product-head roles and predicate-local modifier logic. Introduce a private prepared assertion proof carrying source refs, bound subject/argument roles, predicate construction, completeness, semantic purpose and completion status. Resolve grammatical noun/heading/reported-text roles before state projection: predicate-shaped substrings inside nominal heads cannot create operating relations or supply inherited actors. General nominalization and argument-role rules cover participants and operating-lease headings; no task/text blacklist. Complete active/passive provision, product launch/use/function, factory acquisition/commissioning/startup and measured capacity/customer metrics use this same proof. Finite construction families may be extended at this owner with multilingual semantic controls, rather than further branches inside summary support.
2. **Stage follows proof.** A complete action/function can carry unknown stage and retain its original denial, plan, condition, third-party wording or attribution. Do not manufacture milestone/commercialization/sales from launch or a phase noun. Existing stage wire shape remains unchanged. A private `OperatingRelationSession` assessment API/cache can expose source proofs separately from serialized stage relations. The event/state and source-support projections must share proof, so correcting nominal fragments also corrects their apparent stage observations.
3. **One SourceOperatingSession assessment per exact source owner.** Cache an immutable assessment by the existing owner/material identity and its proven support closure, using the current shared WorkBudget. It returns fact/value topics, financial purpose, complete source-support proof/status and numeric attribution. `fact`, `financial_only`, source support and direct reading compatibility become projections of the same assessment semantics. The legacy 0.8 recognizer remains unchanged. Do not delete complete events by dynamic reason-string membership and do not reopen support through arbitrary unknown-state refs. Source support consumes proven assessment; it does not classify text a second time. A locator/ref check remains necessary integrity validation, not semantic evidence by itself.
4. **Purpose is predicate/object-role scoped.** A customer is supplied `[fair-value measurement software]`: the governed object head is software, with fair-value/measurement as modifiers. In a rule, the company `[measures] [equity investments] [at fair value]`: the governed object is financial. Apply the same role analysis to incentive grants/approval criteria, audit/reporting scope, meta-definitions/disclaimers, going-concern preparation and accounting-standard adoption. Real delivery/collection/performance-obligation mechanisms retain business purpose even inside financial notes. Mixed material can contain an independently valid business assertion while preserving every original character/qualifier. Neither global operating-first nor accounting-first keyword precedence solves this.
5. **Use the existing numeric authority.** Remove newline/digit presence as a numeric attribution signal. Consume the already observed `has_unbound_numeric_cells` / original numeric-quality state for the exact scope and qualified-table owner. True consecutive cells remain readable and generation-unresolved; alphanumeric names, one-value prose and years inside complete prose do not become ambiguous numeric rows. No new number parser, label donation, inferred period or column identity.
6. **Admission consumes the exact view assessment.** Reuse the existing canonical support tuple cache and shared source session. A member's broader group/context fact cannot turn an incomplete view into support; a second member-only interpretation cannot erase a complete closed view. Continuity, original alignment, source IDs, reference envelopes, question/answer roles, source order and existing capacity limits retain their current owners.

An internal private record is enough; there is no need to add an exported investment fact, second task database, new registry version, quota, global cache, generation text classifier, page/company rule, or another independent recognizer. If implementing private proof requires a small same-package helper, make it solely the shared typed role/proof implementation and remove/move the overlapping source-purpose description scan rather than retain both.
