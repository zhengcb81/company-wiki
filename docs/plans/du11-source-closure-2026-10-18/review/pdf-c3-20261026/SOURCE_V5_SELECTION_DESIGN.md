## Minimal correction and interfaces

Reuse the existing three support-use values, not a new wire schema or taxonomy. The proposed source changes consume the same per-owner prepared assessment/cache already introduced in v4.

- For an unbound numeric **row scope**, distinguish a known statement-account role from an operating measure or genuinely undetermined label. Reuse/expose the existing table-purpose owner and its account/operating-measure vocabulary; do not duplicate a financial classifier inside reading/support/budget. Expand that shared account-identity family where needed for tax, depreciation/amortisation, equity/OCI and cash-flow statement row labels. Match a governed row/account identity, not a generic currency/risk/finance word in prose. Proven native table headers may supply the table's role through existing exact membership; a chapter title may not. Complete prose is outside this unbound-row classification path.
- A known statement/account row is `context_only`/raw financial material and creates no independent narrative anchor. Its original bytes/index/source preview remain available. It can still be required context of an independently valid closed scope; removing an independent offer must not remove required IDs or discount costs.
- An unbound operating quantity, capacity/customer count or risk/constraint measure remains readable and `unresolved`: no period/column/value inference, no generation. Unknown stage in a complete qualitative business sentence remains `support` as before. A label that cannot reliably be typed remains `unresolved`, rather than gaining operating status or being blanket-banned; it receives only residual narrative budget after complete support.
- Carry **the existing support use** through source anchor reading metadata → `_budget_item` → `BudgetItem`. A default/None legacy value preserves old callers and explicit reading_plan/1–2 replay. The source assigns this value; the planner never reads payload text or classifies finance/business.
- In the existing reading_plan/3 closure heap, prepend `support before unresolved` to the rank, before value band, novelty/topic visits and raw section priority. Keep the remaining ranking, shared unique-ID costs, dependency closure, span/character caps and bounded heap work. One heap and one budget account suffice; no second planner, two uncharged planning passes, percentage quota or new limit is needed. Context-only entries remain dependency-only and cannot offer independent value.
- Capability belongs to a proven exact support view and its complete required closure. Where an original anchor participates in several views, a complete offer may rank as support only with that proven view's complete source dependencies/cost. This changes which closed material is selected, not the use of any other view; an unresolved view remains unresolved in /4 and cannot inherit another view's generation capability.

Required existing owner expansion for implementation: `narrative_finalize.py` and `narrative_budget.py` for metadata transport/rank; existing `document_understanding/structure/table_purpose.py` if exposing/extending shared row roles is needed. Original v4 source assessment/reading/support owners consume those roles. Consumer/compiler/model code and external /4 wire remain unchanged. ROOT can keep the existing inventory byte-hash mechanism; no new registry or task storage is required.
