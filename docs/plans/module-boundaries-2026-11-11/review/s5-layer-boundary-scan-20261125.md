# S5-09 CWP 边界扫描器

基线固定为 `11ca01c572556d5e28a86c685700cce930bf7902`。本次只验证和改进静态职责检查，运行数据、发布入口和并行工作区由原任务负责。

## 对账和实修

| 项目 | 证据与当前处理 |
| --- | --- |
| 同一顶层包内的私有域 | 原扫描器只用顶层包名。新增用例证明两个各自公布 `__all__` 的子包可以直访私有名称、使用动态属性、交出模块对象或通过 `vars` 取内部状态。现按声明的子包判定这类访问，允许传递公开函数，也允许同一所属域使用内部帮助函数。 |
| 根文件的依赖方向 | 基线只有 `canonical_ingest` 从根层消费来源合同，`scheduled_reading` 从根层装配目录与调度。后者明确归属应用装配。根层工具可使用值合同，测试防止其跨进目录、文档解读等运行实现。 |
| F4 工具与别名 | 将实际运行的 `tools/feedback_loop/` 纳入原有测试。普通导入、点名导入、`import_module` 和 `sys.modules` 中的 `src.company_wiki` 按同一所属模块检查，合法的本仓诊断接口有正例。 |
| 历史公开端口 | 复核原有 6 条精确转发，包括曾部署的叙述 CLI、公告和文档解读路径。应用装配现在可见，历史目录 CLI 的两个 `scheduled_reading.main` 委托也明确记录。相容项只对应真实调用点、目标和公开名称。 |
| 导入循环 | `LayerBoundaries.runtime_import_cycles()` 返回排序后的潜在运行期 SCC。图包含函数内部的延迟导入，排除可静态判断的仅类型检查和仅脚本执行分支。CI 验证诊断算法，组件数量供排程和定位。 |
| 无注解值 | 默认实参已知为外域对象时，保留实际归属并诊断私有访问。未确定所属的参数仍可作为不透明能力对象，变量名本身不推断类型。 |

对基线用例实际复现 10 项失败。第一版子包检查只覆盖明确私有名时，三种动态路径继续失败，因此一起加上。扫正式源码核实结构包路径、3 个私有标题操作和 4 个 PDF 实现模块曾经穿过职责边界。现在由结构、几何计划和策略所有者提供指纹；结构所有者内部仍能按当前部署的完整包树确定身份。文档观察和结构分析共同调用纯词法模块的 3 个公开标题函数，匹配算法保持原语义；读取配方会识别到实现代码的版本变化。

## 验收与余项

沿用 CI 快速合同所执行的 `test_layer_public_boundaries.py`。结构、算法指纹、隔离导入及原增量 CLI 的组合回归通过 179 项。最后一轮增加反射与 PDF 指纹检查后，准确源码版本的边界、指纹和隔离回归通过 103 项，用时 20.65 秒。Ruff、限定生产文件的 Mypy 和 Git 差异检查通过。

最终扫描覆盖 533 个 Python 模块，诊断出 17 组潜在运行期 SCC。F4 的一组由 `host`、`intake`、`local_host` 组成。用 `LayerBoundaries(source_root, feedback_root=feedback_root).runtime_import_cycles()` 可按相同结构复验。

对运行时构造的未知对象和未公开声明独立职责的子目录，静态检查仍有信息边界。源码审计单独安排后续已识别的大环和同域算法重构。历史 API 待部署使用方迁完后再分批退役。

本次隔离测试产物已清理。下一步由 ROOT 复核当前隔离提交，合并后更新父计划。
