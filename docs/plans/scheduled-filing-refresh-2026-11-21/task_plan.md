# 公司文档定期更新与阅读

计划选择 `PLAN_ID=scheduled-filing-refresh-2026-11-21`，工作目录内计划根为 `docs/plans`。Windows 解析时用 `resolve-plan-dir.ps1 -PlanRoot <本仓绝对路径>/docs/plans`，在本次调用环境中留空 `PWF_PLAN_ROOT`。

**当前位置为 P1。** FF 已推送 `main@1ab0a94`。CWP 与 Dashboard 的两张独立卡已派发。共同接口、配置说明与 FF 的隔离验收见 [进展](progress.md)。

## 目标

电脑登录后按日或周增量更新所选公司名单。停机错过日期时补做未覆盖的范围。新找到的财报、招股说明书、再融资材料和投资者关系记录按现有市场能力入库，电话会单独发现和入库。对新原件及有限的既有积压恢复业务内容读取，可使用已配置模型生成原语言摘要。仪表盘配置频率、名单、文种和阅读方式，显示每轮结果和实际缺项。

默认配置建议每周一上午 7:30，按所选时区，自动开关初始关闭。第一批从名单选三家，常态先做本地阅读；正式摘要在同一流程中按现有模型、供应商及预算配置开启。日报模式与周报模式共用同一实现。历史全量回补另外显式选择范围。

## 关键设计

### 1. 调度与名单

1. FF 提供当前 Windows 用户的同一个 Task Scheduler 任务。登录和有限频率的计时检查都运行同一 `tick`。计时建议间隔 30 分钟，关闭或未到期时只读本地状态后退出。Windows 控制同时实例，FF 以本地持久运行键控制去重。关机或睡眠期间保留覆盖水位，登录或恢复后的下一次检查连续补范围。安装脚本按准确的解释器、工作目录、部署配置和绝对路径运行，无须打开 Dashboard。
2. FF 配置引用一个既有正式 Universe。锁定本轮同一名单快照后分页读尽，保存原 owner 的快照 ID 和所选挂牌。首次小范围验收或名单服务不常在线时，可显式选定由同一公开口取得的固定名单。动态模式遇名单服务不可用，继续对账已启动作业与既有阅读队列，等待恢复后再接纳新公司。
3. 按已验证业务身份和挂牌访问各市场。一个公司多挂牌时由所选范围及文件实际来源市场确定候选；同一公司名或 ticker 字符串不能跨市场替代原身份。名单变更在下一轮生效，移出成员保留已采原件和历史。
4. 手动验收用 FF 入口启动同一有限批次。Dashboard 只操作 FF 配置和状态接口。修改频率、名单、文种和模型档位从后续工作生效；关闭后不再接纳新动作，原作业按所属模块的恢复点收尾。

### 2. 增量发现、下载与积压

1. 将到期槽位和实际扫描区间分开。对于同一计划的多个错过槽位合并为一次有界追赶。每个“挂牌／文件类型／来源市场”维护完整覆盖水位，最近窗口保留可配置的重复查找区间，记录迟发布和更正版。首批建议回看 30 日，按真实发布节奏调整。部分结果或截断可重放，不推进越过缺口的水位。
2. CWP 调用既有 provider 的元数据能力，列出有界窗口内候选。仅调用 latest 无法保证找齐周内多份披露。公开返回完整或部分覆盖、游标和已知候选。provider 不支持游标时沿可验证的时间段切分。实际覆盖不明时保留部分状态。先持久记录候选和下一步，再提交覆盖水位。已发现未完成资料留在本轮可恢复积压。
3. 对每个候选优先走 FF/CWP 现有精确复用，再按原 provider、accession/ID、身份、期次和预算显式 `fetch_if_missing`。CWP 通过现有入库锁、真实 SHA/大小和 SourceRef 保存。更正日期或不同 provider 出现同一原文时，由 CWP 按真实字节去重。新版本可并存，保留原历史。
4. 电话会是独立分支。现有配套模式仍供既有调用。FF 复用本地选取和 ET transport，将有证据的 FY/Q 作为查询或采集单位，即使该期财报缺失也可工作。当前 FMP 只支持精确期，期次取自发行人明确披露的财报/会议公告、CWP 现有来源或 provider 自己的可用期元数据。年报不能自动推出 Q4。不确定期次、无覆盖、已到额度、权限不足和未知费用都保留各自结果。保留原语言 TXT/JSON，CWP 以文本读取。
5. 既有已入库未处理文档由 CWP 分页提供精确 SourceRef，限所选名单和时间/文种。每轮先处理新资料，再用余量恢复有限积压。规划建议先用两份并发下载和一份模型摘要实测，按 provider 限速、CPU、磁盘和现有配置调整。覆盖水位与下载、阅读进度独立；一份失败不会阻断同批其他项目。

### 3. 阅读恢复

1. CWP 以确切 SourceRef 进入现行共享解析与文种策略。本地阅读提取必要业务段落、定位和质量，以紧凑结果落到现有工件存储。模型精筛、OCR 或摘要仅按阅读档位及实际配置启用；禁止用现有名称里的 `extractive` 推定没有模型请求。TXT 直接解析，PDF/DOCX/HTML 各走 CWP 所属格式入口。
2. 复用 `scripts/narrative_batch_configured.py` 及现行 AUTO 的账目、lease、outbox、幂等和版本缓存。重复运行先读取原业务产物，只有新原件或有业务意义的新处理选择才生成。强退、回执丢失和付费未知时先以同一 owner 运行 ID 查证。
3. 本地阅读和正式摘要分别提供可公开消费的完成/降级状态。纯格式文档、真实无业务材料和缺预算是具名结果。已产出的正常内容不因可选日志、收据大小或 review 字段缺失而失效。原文、定位、身份、期次及真实成本预算仍由 owner 验证。

### 4. 用量、恢复与可观测性

- 读取、响应字节、时间、请求数、成本和 token 以已有 owner 计量为准。运行编排预留本批工作量，不复制 provider 账本。明确区分没发请求、完成已对账、可能已收费及确证零费用。未知费用保留，不通过换 operation ID、换 provider 或定时到下一天重发同一动作。
- 每个计划只有一份到期/覆盖状态和一个已登记的当前运行。先留意图、运行 ID、子作业键和原快照，再执行外部动作。进程退出后持久状态续接原 `ffjob` 与 CWP 运行。可重试项按已有 owner 可证无重复作用的语义重试，断网和限流使用退避。达到限额即留待下一批，完成过的项仍可查回。
- 用 F4 公开观察关联 `run_id`、所属模块、阶段、业务键、原作业、耗时和用量。新出现的拒绝记录首因并审视门禁必要性，再决定删、放宽或保留以及回归。控制台读诊断，不触发采集。输出只保存引用、状态和必要计量。原件由 CWP 保留，临时文件按 owner 清理，统计持久历史与派生物实际增长。

接口、状态机与固定验收输入在 [interfaces.md](interfaces.md)。实查程序与旧 worker 状态在 [findings.md](findings.md)。

## 总控实施顺序

1. 在 FF 先写确定时钟、到期/遗漏槽位、配置、名单完整分页、部分水位及关闭态的单元测试。用 FF 现有作业目录下的原子记录实现 `status/configure/runs/tick`。 Windows 适配和真实 provider 尚未接入时也能验证编排。
2. 用公共候选 fixture 验证一个窗口两份材料、正式范围正确、已有精确原文零下载。同一入库动作只生成一个 `ff-job`。发现结果由 CWP 保留，exact fetch 尽可能复用已有候选信息，避免同一个提供方窗口逐份重查。必须重新确认时针对该候选，用量真实报回。
3. FF 新电话会种类使用原 ET/CWP 传输与反馈。写“财报缺失但电话会能入库”“精确期无法证明时不发请求”“检测不到原请求费用时找回并等待”的回归。各阶段计量从原 owner 读取，原伴随电话会行为仍通过兼容测试。
4. 编排原件可用→CWP 阅读，支持结合本轮新件和有限本地积压。冻住 CWP 返回的操作 ID 和读回口。素材目录关闭、预算到限、某文件部分失败时收尾原作业，剩余项随下次 `tick` 查回。
5. FF Windows 安装脚本使用当前用户、常规权限、正确工作目录和绝对解释器路径。注册和更新同一具名任务，幂等检查。跨新登录验证配置中的 provider 能力，不依赖父终端临时环境和 Dashboard 进程。测试计划时区和源市场披露日期独立。隔离验证首次安装、重复安装、睡眠/登录重叠、停用与移除。正式停用切配置，回退可撤销本任务注册并保留原件、正式 job 及账目。
6. 接收各仓卡后，先发布兼容的 CWP 公开口，再发布 FF，最后发布 Dashboard。锁定实际运行包和数据根，以受控三市场样本完成组合验收。真实试点发现问题按 owner 送回原复现记录，修复重新通过该大节点后再扩大实际范围。

## 大节点验收

| 验收 | 要查到的结果 |
|---|---|
| 数据与市场 | 三市场身份和公开回执绑定各自正式来源。一轮内两份报告或补发均查到。已有原件的外网下载为 0。非期次 IR/招股/再融资按 accession，电话会与财报解耦，原文 TXT 保留原语言。 |
| 恢复与时钟 | 同时登录、计时和手动提交产生同一槽位，重复重启和 DST 日期边界都能查回原作业。分别在发现后、入库后、模型发出后/收到后强退，验证无重复网络用量和费用。未知用量的原尝试保留。 |
| 文档阅读 | 多语言原文、低价值跳读、已有原件未处理、新版与旧版并存、真实摘要与缓存恢复。文本资料不触发 PDF 路径，正式输出含业务依据和定位。 |
| 使用与成本 | 浏览状态和保存设置无下载。关闭后新作业为 0。保留在途状态。展示成功、部分覆盖、待重试、未知用量，能确认运行目录、续做和撤回的方法。每轮统计耗时、请求、原件与派生增量。 |

各仓交付前用一名独立 agent 复核完整度和质量，修完发现并复测。总控只在组合和正式启用做整体验收。发布按属主分仓提交；每张卡回传版本、测试、恢复证据和配置接线方式。主线循环的计划与目标单独维护。
