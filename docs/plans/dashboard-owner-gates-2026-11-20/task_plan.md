# Dashboard 公开接口误拒修复

## 目标

修复 2026-11-20 七张 Dashboard owner 卡中已复现的接口误拒。用现有 ID 和冻结数据复验。确认缺的是数据、接线或接口能力时，记录确切缺口并按责任仓处理。

## 分工与边界

| 责任仓 | 施工范围 | 关键验收 |
|---|---|---|
| company-wiki | 已验证的跨市场挂牌与原件归属用可复用公共凭据组合，去掉部署标签充当验证条件的路径 | 已有港股原件、正确/冲突归属，A 股与美股回归 |
| filing-fetch | 本地准备与查询共用请求构造，保留 CWP 具名原因 | 有无发行人关联两种复用未命中，无新增采集 |
| revenue-forecast | 终态纯读，按角色登记多来源原作业、关联已有快照，消除重复记录引起误拒 | 已成功及未知作业恢复，原 W12 冻结材料只读或隔离登记 |
| StockWiki | 研究关联以权威挂牌事实为准，引用补充独立降级 | 既有阿里/MDB 研究，药明正式引用和不可验引用 |
| IQS 服务与独立 UI | 真实监听地址接线，预览与提交职责归位，固定结果回跳 | 同一结果/观测，隔离名单断线查回，旧 UI 已通过项维持 |
| Dashboard | 固定原件、状态投影、可选引用与回跳、名单回执、真实指标公开接线 | 七张卡原 ID 对照，隔离 HTTP 和浏览器组合 |

业务库、另一个 Dashboard 项目的工作树及 W12 主计划不作为测试写入目标。每仓先复现再实现。总控负责组合回归、独立审查和发布整合，同一工作区的已有改动保留。真实缺数据优先复用已冻结字节；采集、收费与生产登记分别确认必要性和已授权范围。
