## 所属层复核

- StockWiki 的公开研究命令先校验可选引用配置，再由引用投影和每条引用重复观察。缺文件、损坏 JSON 或解析器原生异常原本能阻断研究。现在由所属引用投影每次准备一个读连接，失败时保留基础研究并报告具名原因。
- RF 的已有作业登记额外比较 StockWiki 内部版本、展示字段和整份观察记录。已改为按公共证明、真实发行人和挂牌坐标、报告主体、原件与期间判断。入册前复核有业务意义的绑定，重复登记返回原有谱系。
- RF 独审用实际 StockWiki 公开证明复现了候选的新误拒。用于证明历史原件归属的同发行人辅助挂牌可已退市，按收据和历史坐标确认即可。选中挂牌仍按当前解析结果验证。

## 部署复核

- 现役 F4 IQS 与一般研究资料使用不同的 StockWiki 工作区。两个工作区对中微的实际实体和挂牌键不同，股票代码相同不能直接互换。IQS 和现场 Dashboard 快扫继续消费其现有 r25 身份；三市场原件、研究和 RF 用业务主库已验证的公开身份做隔离组合。各自的外部数据沿其拥有者公开口读取。
- Dashboard 全检出验收通过后，独立发布包首次启动遗漏 `contracts/openapi.yaml`，旧进程已恢复。根因是实际运行包只导出后端代码和网页资产。发布内容加入同提交的整个 `contracts`，核对原始 OpenAPI 字节，并从实际包启动隔离端口验证界面和业务接口后才重试切换。
- 扩展回归分清了已授权的行为变更与四个实现问题。可选导航局部降级和历史原件精确读取使用新合同正反例。原件流在 EOF 校验和关闭之后才发终块，真实字节限额统一处理两种长度声明。指标磁盘故障统一由存储层报告，应用通过公开快照接口使用固定数据和定义。
