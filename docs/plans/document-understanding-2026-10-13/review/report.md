# 深化复审：把策略配置变成实际阅读能力

## 结论及边界

一个共享引擎加多份阅读策略仍是合适的架构。应把它做成可靠的单体内处理链：来源读取 → 格式/布局 → 章节和角色 → 文档策略绑定 → 完整证据选择 → 原语言摘要。增加类型主要增加配置和样本；格式、依赖、预算、来源和恢复共用代码。

目前设计比实际接线完整。最大的风险并非类型数量少，而是配置存在却不生效、上下文不完整却报完整、基准测了错误目标或给出错误归因。以下缺陷主要在未并主线的 DU 分支；不是声称已发布三仓架构改造全部失败。

读了主线设计、四个工作树交接与相关源码，三个独立 agent 分别审查架构、策略、评价。ROOT 复跑三组纯内存探针；另由独立 agent 用真实微软 HTML 验证既有公共前端。0 付费模型、0 原件写入；少量官方网页仅用于文档形态研究，未下载到资料库。本轮没有完成真实模型语义审查。

## 2. 测什么必须重新对齐

只保留三种测试目标类别，不增加生产权限字段：

| 类别 | 示例 | 如何判定 |

| required_business | 新业务进度、出海订单、客户验证阶段、经营指标及其解释、项目延期、监管约束 | 在已读取范围内应找到完整支持；关键事实不能漏；普通业务事实按冻结目标计分 |
| disposition_context | 文档是制度/全文/摘要，来源日期、读取缺口、合法无业务 | 在 metadata/route/coverage 评价；不要求进入业务摘要 |
| correctness_if_emitted | 三表常规数字、目录页数、非重点历史值 | 不强迫抽取；一旦输出就查出处/单位/期间/语态，不能错 |

发现原调查 cn-ir-policy 文件名虽像制度，正文实为 2023-04-28 投资者关系活动记录，含利用率、扩产、OLED验证供货。它应作为“标题误导但正文有价值”的正例，真正制度负例需另找。保留原始调查记录并加纠正，不改历史证据冒充当时正确。

基准旧报告中的 0.175→0.324、0→0.350 等幅度暂不采信：既有分母不完全配对，还有错误 oracle、错误目标与错误 HTML 入口。它们是需要复查的观察，不应驱动调参。修复后以相同原件、相同已读范围、相同预算和相同业务 gold 重算。观察范围扩大的收益另报，不混在算法提升里。

原 holdout 为 A/H/US 2/1/2，且已用于分析。凡根据其内容修改规则的样本转为回归集；最终保留未参与调参的新公司。不能把五个旧文件继续称全新盲测，也不能因为缺资料就加人工许可。

## 3. 阅读策略应由四层组成

1. **通用业务关注点**：业务模式、行业变化、主业进展、新产品/第二曲线、海外、客户订单、产能项目、约束和风险。各文档复用。
2. **文档用途**：定期回顾、历史业务基础、融资项目、事件更新、管理层问答、展示材料、行政用途。决定先读哪些章节、保留何种证据。
3. **披露形态修饰**：A/H/US、正式表单、全文/摘要、原稿/修订/补充、载体、语言、报告期/发布日期/期后事件。上市地不能代替文档用途。
4. **可选经营模式修饰**：软件订阅/消费、零售店网、制造产能/认证、生物医药/CDMO阶段。不按公司名称固化，不让行业标签生成缺失事实。

同一事件的 release/deck/call 允许多份原文来源；后续在证据层识别重复事实，保留引用，不复制全文或建立第二研究库。跨期比较仅在主体、口径、期间可比且证据齐备时做；先保证单文档可靠。

策略不能只列关键词，还须说明：要回答的业务问题、哪里可能有答案、什么证据足够、哪些限定不能丢、哪些相近概念不能混、找不到时如何诚实表达。详见[矩阵](strategy_matrix.md)。

## 4. 引擎能力升级

保留共享处理链，补四项通用能力：

- **低成本全局侦察＋按缺口补读**：原生标题/正文/尾部均取样；优先恢复业务表、图注、跨页问答，有限 OCR 仍走既有配置与预算。扫描缺口不能当无价值；不为所有页自动 OCR。
- **完整证据与预算统一**：unit→依赖图只建一次；依赖、共用脚注和语态限定去重计费；先闭合后选取，不能先截断再标完整。多个项目不因共享“建设期”关键词混合。
- **主题覆盖选择**：业务问题的真实证据优先，支持不同主题和正负信息；不强制每文档填满每主题、不强制选固定百分比。稀疏文档可不摘要；招股书可以读较大部分。
- **版本与空间复用**：沿用现有 AUTO lease/outbox 与 generation，绑定实际用到的父/子 profile、结构/选择/提示版本及模型配置。相同版本0模型调用，局部策略变化不全库重建。持久化精选引用、短摘要和覆盖记录；不保存每阶段全文/全截图。

图表 OCR 或跨语言语义对应不宜完全靠规则认证。先保留坐标/标题/脚注并标读不到；真实模型只在原有大节点检验忠实度。增加更复杂的工具要由测得的缺口证明价值，不预先引入大型多模态框架。

## 6. 分工与完成标准

ROOT 统一处理 R01–R10 的跨层根因、原包接收与正式接线。外包提供新的文档策略、业务策略和布局辅助能力，路径互斥；不让多个 harness 同时改原核心模块。

最终按 A：目标/反例、B：共享链离线、C：真实原件/模型三个集中节点验收。日常 CI 只保留决定性小反例；多公司/真实模型/性能与母计划 G2/G4/G5 合并。此次完成的是审查、计划和施工卡，不能标记上述生产缺陷已修复。
