Initial confirmed facts: `SourceOperatingSession.groups` already maps bounded temporary analysis text back to exact original unit refs; `native_range_unit` explicitly requires one physical page and must remain strict. `narrative_reading._candidates` can retain original members when a carrier is unavailable and already builds multi-member analysis groups. `citation_support_views` projects complete actual support and separate context refs without a fabricated carrier. Existing operating-state context merges attribution name classes; it does not establish a concrete unique/collective product antecedent merely because a context ID was supplied.

## Decision: one source closure plan, two kinds of evidence

Keep source acquisition/parsing, native physical proof, operating referents and summary projection separate. The minimal source-owned closure step belongs inside `source_catalog/narrative_reading.py::_prose_reading_packages` before material-carrier replacement and context-graph budget allocation. It consumes already-read original units, native provenance, observation ordering, structure sections/furniture and original reading scope. It returns a bounded reference-only package plus physical and referent diagnostics; no newly concatenated canonical source, parser, task database or model call.

- **Physical split assertion:** unfinished prior-page body + actual next-page continuation are both factual support, each retaining original page/locator/parser and all qualifiers. Neither half alone becomes a complete new statement.
- **Anaphoric statement:** the actually quoted event remains support; uniquely identified prior product-family material is required context, with explicit original refs and collective scope. A generic chapter title is not a product antecedent. Do not rewrite “该系列” into one guessed member.

Use one existing package graph to charge and select both. Source operating relations supply actor/object/qualifier observations; source reading decides readiness. Summary task/card layers only project references and readiness. Unknown proof yields finite deferred/unsupported diagnostics, not a manual permit.

### Important ownership traps

1. `SourceOperatingSession.owners = {uid:gid ...}` assigns one owner per original body member. Overlapping analysis groups silently make the last owner win. A new physical cross-page closure must consume/replace its old body windows. A prior window can be *context* for another event without also being inserted into the second analysis group's body ownership.
2. `_candidates` only remaps member/anchor/required IDs through carrier origins in its current `budget_packages` rewrite. New `native_analysis_views` must use actual material IDs after carrier composition, while `_context` deliberately receives original IDs and maps them through `_selected_unit_spans`. Do not mix those two namespaces. Add a carrier+context integration RED.
3. `_original_refs(owner, refs)` currently maps offsets through the owner's segments without inspecting each ref's `unit_id`. Existing five ref families originate in the target analysis coordinate system, so that is appropriate today. New context refs already pointing to original units must not be blindly remapped as target offsets. Branch on namespace/validate each ref or keep the bounded referent result separate from the five existing fields. Test explicit target/context ranges that share numeric offsets.
4. Current contexts are often sorted by hash IDs. That ordering is reference bookkeeping, not “nearest antecedent”. Resolve using actual source ordinal/page/section observations; never choose the lexicographically smallest hash or last encountered dictionary item.

## Adjacent-page physical plan

### Necessary observations

Build once-per-source indexes from existing `pipeline.observation.units`: by originalID, source+physicalpage, ordinal, actual active section/reading profile and native body status. Only examine adjacent physical pages. A continuation candidate requires:

1. Last **observed body** of pageP and first **observed body** of pageP+1 in actual reading flow. Both pages and their endpoints must actually have been read; partial/opaque prior page is not evidence of absence.
2. Same original parent, parser/version, role, activity/section scope, measured coordinate frame/rotation/page dimensions/font compatibility. Cross-source, QA-turn, project, table, new heading or meaningful unknown intervening material remains a boundary.
3. Prior body is physically unfinished and current unit requires it; a new-page char0 is not proof of an independent assertion. A complete explicit independent new statement must not be forced into an unrelated prior fragment merely because its page begins.
4. A positive body-lane/flow proof on both pages. Equal `column=None`, `same_column`'s permissive fallback, matching x margins alone, or the absence of detected cuts are not proof of a single column. Use actual `layout_hints.columns` lane evidence or a bounded measured body-band witness under the current geometry owner; absence remains unknown.
5. Intervening units are **positively identified** original running page furniture only. No skip-by-regex-only/company/page position, no arbitrary “first2blocks are header/footer” rule. A page-number-like business value is not automatically furniture.

### Existing furniture/column ports

`structure/layout.py::order_units/_running_furniture` already observes repeated edge-band text or parser-declared furniture. `Ordering.running_header_ids` and `REPEATED_RUNNING_HEADER` diagnostics distinguish those units. `structure.coverage.excluded_furniture_unit_ids` is a union of **TOC and running furniture**; do not blindly treat the entire union as skippable page header/footer. Current `layout.continues_visually` rejects all cross-page pairs, despite a broader old module docstring. `layout.same_column` returnsTrue when either column is unknown; it is not sufficient for cross-page proof.

`layout_hints.columns.detect_document_lanes` learns lanes/cuts once; `layout_bridge` projects observed `text_column` into layout. `no_column_gap`/`insufficient_geometry` do not automatically certify a page as single-column. A bounded witness similar in responsibility to current native `tail_column_proof` can establish a physical body band, but same-page tail witnesses cannot simply be relabeled as cross-page authentication. All source/frame/font/flow guards remain.

For the documented p16→17 case, both pages have compatible native frames and dominant body font; current column metadata isNone and no cross-page edge has passed. The real registered-symbol font variation must not fabricate a product/scope change, but compatible dominant fonts likewise cannot manufacture a missing lane proof. If the source owner cannot establish enough evidence under the current caps, the correct first implementation is a declared dependent/open/deferred task, not a fabricated complete cross-page quote.

### Representation and source verification

Generate one finite reference-only package whose ordered `member_unit_ids/anchor_unit_ids/citation_support_views` include both original parts. Preserve pageP and pageP+1 locators and exact strings. `SourceOperatingSession` may use its transient analysis separator logic to recognize split CJK words while returning original split refs. `source_cards.text` continues to join actual support with newline; it does not invent source bytes or remove a line break in canonical text. Each original span is replay-verified using the existing parser, not a new aggregate invented locator.

Prefer keeping those few original members rather than extending native-range schema. If per-page carrier compression is useful, each per-page carrier must independently satisfy `native_range_unit` and the outer package still contains multiple carrier refs; count original proof cost across all pages, not merely the number of compressed carriers.

## Unique / collective antecedent plan

Keep geometry responsible for physical support. Extend the existing operating-state/source-session responsibility with a finite **observed dependency**, not a general pronoun-solving engine:

- Only consider a source-language dependent expression in an actual object/subject position, not every occurrence of a strategic/future/negative word from `_prose_reading_packages.dependent_statement`. That existing split guard intentionally mixes many different dependencies and is not a referent resolver.
- Candidate antecedents must be actual explicit product/system/family noun-phrase ranges from a bounded preceding source scope. Reuse prepared matching views and existing NP/actor/object rules; do not add another product dictionary to the PDF adapter or source-card compiler.
- Require either one explicit referent or one explicitly enumerated **collective family scope**. A list of A/B/C can remain one collective source context if the source establishes it. Do not assign the downstream group statement to A alone, or convert a collective claim into several per-product milestones.
- Return original `unit_id+char_start+char_end` refs, statusunique/collective/ambiguous/missing, and required original-context IDs. The method may conservatively returnunknown when grammar is insufficient. This is a proposed small method/result, not an existing API that already does this.
- Context must have the same original, actual adjacent section/speaker/project scope, correct order and no competing meaningful intervening source. A generic heading is not a named product; a question is not an answer's factual support; a third-party entity remains third-party. More than one plausible series, unread prior context, contrast/new-topic boundary or resource stop remainsunknown/deferred.

Current `_bind_event` only inherits `last_actors/last_topic` **within its target matching view**. Existing external contexts contribute attribution name classes, not product referents. Therefore appendingcontextIDs alone fixes neither the proof nor the meaning. One possible narrow port is `OperatingRelationSession` returning a separate bounded referent observation, with `SourceOperatingSession` mapping its target refs and retaining already-original context refs. ROOT should name the concrete method during implementation, without creating a new library/service/store.

For anaphoric cards, keep the event's exact body as support and actual prior series declaration as requiredcontext. In public artifact replay the consumer must receive both scopes and collective/unknown diagnostics. A bare dependent `claim.text` without re-openable context is not enough. No source word should be replaced by a guessed product name to make the text readable.

- One parent `WorkBudget(16_000_000)` for the attempt, existing96selected spans/48,000selected characters, current56KiB draft/64KiB final/32KiB execution. No second allowance or retry with a fresh balance inside production.
- Build metadata indexes in one charged pass. At most one pending physical page boundary and a bounded preceding source window per active scope; no all-pages pairwise search. Reuse `OperatingRelationSession` prepared views and `SourceOperatingSession` result/fact caches. Charge before constructing analysis text, mapping new references, scanning context or sorting bounded candidates.
- Maintain the established8original-body-unit/4original-block/2048character physical closure envelope and account for necessary antecedent material, not merely compressed carrier IDs. If a dependency needs more than this scope, retain unknown/deferred under existing global selection limits; do not hide it outside the accounting as freecontext.
- Count cross-page block identity as `(source_id,page,pdf_block)`: block numbers restart on each physical page. Extending the current same-page `set(pdf_block)` directly would undercount duplicate block numbers across pages and silently bypass the4block bound.
- `SourceOperatingSession._prepare_group` already charges2×member characters+membercount before constructing its transient view; `fact` charges6×text before recognition, and relation parsing charges the same parent. A proposed bounded referent pass must reuse those prepared views and reserve its actual incremental work rather than rescan a chapter or restart on budget exhaustion.
- Required original context enters the existing graph before `finalize_selection`; selection and draft allocation cannot later append it for free. If final96/48k/byte limits cannot hold the closure, defer the whole dependent card. Other independent valid cards continue; no global authorization stop.

The real p17/paragraph9–14 example spans original blocks7,8,9,10,11: **five distinct blocks** if all context is necessary. It cannot be called a valid4block closure by counting only three body blocks or one compressed carrier. Either an actual smaller sufficient original context is proven (without dropping source qualifiers or guessing a series), or that exact example is honestly deferred. This is an important acceptance boundary, not a reason to raise the cap silently.

## Portable behavior RED to write before implementation

1. **Physical two-page positive:** a new-company CJK or English statement split between actual last/first body units, same proved lane/frame/scope and only explicitly identified running furniture between; one support scope carries every original part/ref/qualifier and exact source hashes. No cross-page native_range is created. The private matching view maps every event range back to the proper original unit.
2. **Independent next-page positive:** prior body already ended or the next actual section/statement is independently complete; do not contaminate the new statement with another product or previous risk. Singletons remain unassessed unless a specific closure proof exists; don't reproduce HK0/7 by rejecting every nonpunctuated block.
3. **Physical negatives:** columnNonewithoutpositivewitness, incompatible actual lanes/frame/font/source/role, table/QA/project/newheading, page gap, unread previous page, arbitrary skipped body, unknown footer, TOC in excluded-furniture union. No fake cross-page association on matching margins/IDs alone.
4. **Unique/collective context:** CN/繁/EN “该系列/該系列/these products” follows one explicit family or enumerated collective. Event refs stay inbody, context refs in the actual original antecedent units, no single-member expansion. Similar objects in two competing adjacent paragraphs, another company/question, generic title only and unavailable prior unit defer honestly.
5. **Forced window boundary:** original product enumeration precedes dependent event across4block/8unit cut. Within-cap minimal requiredcontext survives through graph selection, scoped model view and public reopen; over-cap case isdeferred, not a truncated cheaper fact. Include original negation/future/customer-verification qualifications.
6. **Ownership/carrier mapping:** original member cannot simultaneously belong to two analysis owners; a separately reused context is allowed. A per-page carrier plus a raw second-page unit has correct original-ID origins. Context ref offsets identical numerically to target offsets must not be remapped into the wrong unit.
7. **Cost/id/replay:** zero/exhausted work performs no neighbor scan; no second classify/parse, no hidden context work or text copy. Repeated block numbers on different pages count separately. All positive source refs are replayable; raw originals/strings/IDs and paid old runs remain immutable; changed closure code updates actual current dependency identity.

Existing test owners to extend at one concentrated node: `test_reading_native_continuity.py`, `test_reading_native_carriers.py`, `test_reading_production_selection.py`, `du4_operating_states/test_b_synthetic_specs.py`, `test_c_contract.py`, `test_root_boundaries.py`, `tests/unit/test_narrative_native_ranges.py`, `test_source_summary_tasks.py`, plus existing exact-public-context and paid-recovery integration controls. Reuse existing oracle carefully: `closed_group_support._edge` currently forbids cross-page joins. A new physical proof needs an explicit test adapter/oracle observation; never just label any cross-page group`native_continuity` to obtain support. Tests should check each page anchor/ref and the proved original closure rather than weakening `_edge` globally.
